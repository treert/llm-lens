# 蒙特卡洛模拟验证 · 设计文档（v2：流式架构）

在现有理论曲线（F^M / Gumbel / 一阶近似）之上叠加真实随机采样结果，
直观验证理论曲线，并把 README §5.3 讨论的近似误差变成可见现象。

## 0. 与 v1 的区别

v1 方案：T 次独立试验 × 每次 K 个向量，总成本 $T \cdot K^2 N / 2$，且只覆盖
当前一个 K。v2 改为**单遍流式**：向量逐个生成，第 $i+1$ 个与之前 $i$ 个
点乘，**每对点积全程只算一次**，一次运行覆盖 $2 \dots K_{\max}$ 的全部 K：

- 总成本 $R \cdot K_{\max}^2 N / 2$（$R$ 为并行轨迹数），比 v1 低 1~2 个量级；
- 过程天然可中断/继续（保存 $(i, j)$ 进度即可），中间状态可持续刷新；
- 瓶颈从 CPU 转为**内存**（需保存全部已生成向量），$K_{\max}$ 由内存预算
  在启动时算出并显示；
- maxPerRun 池"一池两用"：行聚合给曲线 1 中位数带，列切片按需重建
  任意 K 处的 max ρ 密度——v1 想做的 max 密度直方图以更强形式回归
  （见 §1、§6）。

## 1. 目标与统计映射（核心）

流式运行产生三类累积量，**各自验证的对象不同，不能混淆**：

| 累积量 | 收敛/对比对象 | 落在哪张图 |
|---|---|---|
| ① 点积槽位直方图（全部 $\rho_{ij}$） | **单对 beta 密度**（曲线 2 **绿线**，引理 6.1） | 曲线 2 阶梯线叠加 |
| ② 每轨迹运行最大值 $\max_{i<j\le K}\rho_{ij}$ | 曲线 1 的三条**中位数**理论线；任意 K 处的 **max ρ 密度**（蓝线） | 曲线 1 轨迹线 / 中位数带；曲线 2 按需密度重建 |
| ③ 点积总和与总数 | sanity 指标：均值应 ≈ 0（对称性） | 统计栏文字 |

要点与推论：

- **① 的点积直方图验证的是绿线（单对 beta）**，它与 K 无关，全程池化成
  一份即可，**无需按 K 分别保存密度数组**。**蓝线（max ρ 密度）同样可
  验证**：maxPerRun 池在每个 K ≤ 当前进度处都保留 R 个 max 样本，用户
  滑动 K_select 时对该列**按需分 bin / KDE** 重建密度并叠加曲线 2
  （R<8 不显示；8≤R<32 阶梯直方图；R≥32 切换 KDE，带宽取 Silverman
  准则 $h=0.9\min(\hat\sigma,\,\mathrm{IQR}/1.34)\,R^{-1/5}$），
  光滑度随累计 R 单调提升。
- **"第 K 步全体点积的均值/中位数"不随 K 变化**：每对 $\rho_{ij}$ 的边缘
  分布恒为同一个零对称 beta，均值、中位数恒 ≈ 0，画出来是平线，**不画**；
  均值仅作 ③ 的 sanity 显示。随 K 增长的是**极值**，故 ② 记录运行最大值。
- **为什么需要 R 条轨迹**：单条轨迹的 $\max(K)$ 是一条随机"破纪录"路径
  （单调不减、阶梯状），R=1 时直接画它（原始路径，教学价值高）；
  $R>1$ 时每个 K 有 R 个 max 值，跨轨迹取**中位数与 IQR（25%/75%）**，
  得到可与理论中位数线对比的估计与涨落带。
- **R 的统计精度与分批累积**：max ρ 的相对散布 ~ 5%（N=1024 量级），
  中位数估计涨落 ~ $1.25\sigma/\sqrt{R}$（R=16 约 ±1.7%，R=64 约 ±0.9%，
  R=256 约 ±0.4%）——理论线之间的差距为 5%~25%，R=16 已足以判别；
  但要得到光滑曲线与可靠的 IQR 带，需要更大 R。解决办法是**分批**：
  一批轨迹跑完后其向量内存即可释放（只保留 maxPerRun 曲线与直方图
  累积量，每批仅 ~50 KB），再跑下一批并**跨批池化**统计。内存恒为
  一批的规模，累计 R 随时间无界增长（见 §5、§6）。
- 大 K 端轨迹中位数可能略高于 F^M 线：点对实为两两独立而非相互独立，
  这是 F^M 独立性近似的真实误差（README §5.3），属预期现象。

## 2. 流式算法

```
状态：V[r] = Float32Array(K_max × N)    // 已生成向量，每轨迹独立分配（见 §4.3）
      hist[B+2] = {sum, count}          // 点积槽位数组，两端开口
      maxPerRun[R][K_max+1]             // 每轨迹运行最大值（Float32）
      sumAll, cntAll                    // 全体点积和与计数
进度：(k, r)  // 轨迹 r 正在生成第 k 个向量（k 从 2 起）

for k = 2 .. K_max:
  for r = 0 .. R-1:
    v = 采样单位向量(N)                  // 高斯归一化，见 §3
    m = -inf                             // 本向量与历史向量的最大点积
    for j = 1 .. k-1:
      ρ = dot(v, V[r][j])
      更新 hist(ρ)；sumAll += ρ；cntAll++
      m = max(m, twoSided ? |ρ| : ρ)
    maxPerRun[r][k] = max(maxPerRun[r][k-1], m)
```

- 内层 $(j)$ 循环与 $(k, r)$ 循环均可在任意点暂停：保存 $(k, r, j)$ 三元组
  即完整进度；用 ES6 **generator** 实现则状态由闭包自动保持（见 §5）。
- 每个 K 完成后：$\texttt{maxPerRun}[\cdot][k]$ 即该 K 处的 R 个样本，
  绘图时跨轨迹排序取中位数/IQR（$R \le 64$，每帧排序成本可忽略）。
- 双侧模式：直方图累积 $|\rho|$（与曲线 2 现有的"×2 折叠"绿线对应），
  运行最大值取 $\max|\rho|$。

## 3. 采样原理

- **球面均匀采样：高斯归一化**。$x = z/\|z\|$，$z \sim \mathcal N(0, I_N)$。
  多元标准正态各向同性（旋转不变），方向在 $S^{N-1}$ 上均匀，与理论假设一致。
- 均匀 RNG：**mulberry32**（可设种子）；默认随机种子，可选"固定种子"复现。
- 高斯 RNG：**Box–Muller**，$z=\sqrt{-2\ln u_1}\cos(2\pi u_2)$，
  缓存 $\sin$ 支路下次复用。
- 生成与归一化成本 $KN$/轨迹，相对点积项可忽略。

## 4. 数据结构

### 4.1 点积槽位直方图（hist）

- 槽位范围取自曲线 2 当前横轴 $[x_{lo}, x_{hi}]$（约 ±(4~6)/√N 量级），
  内部 $B=240$ 个等宽槽，**首尾两槽开口**承接 $|ρ|$ 超出范围的离群值。
- 每槽存 `{sum, count}`：count 用于密度化高度，sum 用于精确合并均值
  （③ 的 sanity 也可由 $\Sigma$sum/$\Sigma$count 直接读出）。
- 绘图为阶梯线（`type: 'line', step: 'end'`）：高度 = count / (cntAll × 槽宽)，
  与 value 轴天然对齐，无需像素换算。

### 4.2 运行最大值（maxPerRun）

- 每轨迹一条 `Float32Array(K_max + 1)`，单批 R 条共 $4R(K_{\max}+1)$ 字节
  （R=64、K_max=2000 也仅 0.5 MB），无需 v1 设想的"定长 1000 检查点数组"
  ——每 K 直接记录成本为零，检查点压缩留给绘图层（对数轴抽稀即可）。
- **跨批保留**：每批结束后向量数组 V 整体释放，maxPerRun 曲线与
  直方图累积量追加到全局池（每批 ~50 KB，百批也仅 5 MB）。
- **一池两用**：maxPerRun 池按"行"（固定轨迹，跨 K）提供曲线 1 的
  中位数/IQR 聚合；按"列"（固定 K，跨轨迹）提供该 K 处 max ρ 的
  R 个样本，供曲线 2 按需重建密度。列切片分 bin 的成本为
  $O(R \times \text{网格数})$，滑块拖动实时完成。

### 4.3 内存预算 → K_max（启动时计算并显示）

以下 R 均指**每批轨迹数** $R_{\text{batch}}$；跨批累积只增加 maxPerRun 池
（可忽略），不增加向量内存。向量存储占绝对主导：$4 R K_{\max} N$ 字节。
给定内存预算 $B_{\text{mem}}$（默认 **2 GB**）与**单批**运算预算
$C_{\text{ops}}$（默认 $5\times10^9$ 次乘加，约 10–20 s/批）：

**JS 内存限制与分配策略**：

- 浏览器对**单个 ArrayBuffer** 有 ~2 GB 上限（Chrome/Firefox 64 位；
  Safari 尤其 iOS 更低），故向量按**每轨迹独立分配**
  （`V[r] = Float32Array(K_max × N)`，单块仅 MB 级），永不触碰单块上限；
- 标签页总内存无硬编码上限（64 位桌面浏览器受系统 RAM 约束，实际
  可达数 GB）；分配包 try/catch，失败则 K_max 减半重试（最多 3 次），
  仍失败提示降低 N 或 R；
- 默认 $C_{\text{ops}}$ 下 K_max 实为**时间封顶**（见下表），实际分配
  仅几十 MB；2 GB 预算只是保证内存永不成为瓶颈，不会真的占用 2 GB。

**首次运行实测预算（probe）**：2 GB 只是名义上限，真实预算在**首次点击
「开始模拟」时实测**（每会话一次，结果缓存）：

1. 以 64 MB 步长渐进分配 ArrayBuffer，**每 4 KB 页写 1 字节**——未触碰
   的页是惰性提交的，只分配不写测不出真实可提交内存；
2. 分配失败或达 4 GB 上限时停止，记录峰值并**立即全部释放**；
3. **真实预算 = min(实测峰值 × 70%, 2 GB)**：30% 余量留给页面本身、
   ECharts 画布与 GC；
4. 控制区显示：`实测可分配 ≈ 1.6 GB → 内存预算 1.1 GB`；
5. 兜底：首个 64 MB 即失败 → 回退 256 MB 并提示；探测耗时 ~0.5–2 s，
   期间状态栏显示"正在探测可用内存…"。

$$K_{\max} = \min\Bigl\lfloor
  \frac{B_{\text{mem}}}{4RN},\;
  \sqrt{\frac{2C_{\text{ops}}}{RN}},\;
  N^2 \Bigr\rfloor,\qquad K_{\max} \ge 2$$

示例（$B_{\text{mem}}$ = 2 GB，$C_{\text{ops}}$ = 5×10⁹，K_max 均被时间预算封顶）：

| N | R | K_max | 实际内存 | 估算总耗时* |
|---|---|---|---|---|
| 1024 | 16 | ≈780 | ≈51 MB | ~10–20 s |
| 1024 | 64 | ≈390 | ≈102 MB | ~10–20 s |
| 4096 | 16 | ≈390 | ≈102 MB | ~10–20 s |
| 8192 | 1 | ≈1100 | ≈36 MB | ~10–20 s |

\* 按 ~5×10⁸ 次乘加/秒，为**单批**耗时；实际首片执行后实测校准并动态
显示 ETA。中位数涨落 ~ $1.25\sigma/\sqrt{R_{\text{累计}}}$，随追加批次
单调下降。

## 5. 中断 / 继续 / 刷新

- **generator + 时间预算分片**：`simulate()` 为 generator，每完成一个向量
  （或每固定个数点积）`yield` 一次进度；驱动器循环 `next()` 直到单片
  ~30 ms 预算耗尽，然后 `setTimeout(0)` 让出事件循环。状态全在闭包内，
  无需手动序列化 $(k,r,j)$。
- **暂停/继续/重置（三态手动控制）**：暂停 = 停止调度（闭包状态自然
  保留，图上数据不动）；继续 = 恢复调度；重置 = 丢弃生成器并**清空
  全部池化数据与图上叠加**、中止自动追加，回到初始空闲态。
- **分批与追加**：一批跑完后释放向量内存，统计量入全局池；「追加一批」
  以**延续的 RNG 流**新建一批轨迹（固定种子下全过程确定）。可选
  "自动追加"：一批完成后自动开始下一批，直到用户停止或参数变更。
- **帧率控制**：图表重绘节流至 ~4 fps（每 ~250 ms 或每片结束时刷新，
  取较稀疏者），避免 ECharts 重绘超过模拟本身的开销。
- **状态栏文字**：`运行中 K=342/780 · 轨迹 11/16 · 内存 51.2 MB ·
  已用 6.3 s · 预计剩余 12 s`（ETA 首片后实测校准）。

## 6. UI 集成

控制区新增：

- 控制状态机：空闲 →「开始模拟」；运行中 →「暂停」「重置」；
  暂停中 →「继续」「重置」；一批完成 →「追加一批」「重置」
  （勾选"自动追加"则连续滚动，期间仍可随时暂停/重置）。
- 每批轨迹数 R 下拉：1 / 4 / 16 / 64（默认 16）。R=1 画单条原始路径，
  R>1 画中位数线 + IQR 带（带在累计 R ≥ 8 后显示）。
- 「固定种子」复选框 + 种子输入（可选）。
- 启动时按 §4.3 公式显示：`N=1024, R=16/批 → K 上限 780（每批内存
  ≈51 MB）`（首次运行先实测内存预算，见 §4.3 probe，显示
  `实测可分配 ≈X GB → 内存预算 Y GB`）；状态栏同时显示
  `累计轨迹 R=80` 与当前中位数涨落量级 $\pm 1.25\sigma/\sqrt{R}$。

图表叠加：

- **曲线 2**：两个模拟叠加层。① 点积阶梯直方图（灰紫色），叠加在
  绿线（单对 beta）区域，随运行逐渐贴合绿线；② 当前 K_select 处的
  max ρ 模拟密度（另一配色），从 maxPerRun 池该列按需重建，
  滑动 K 滑块即时切换、运行中随进度实时刷新。
- **曲线 1**：R=1 时叠加一条阶梯状轨迹线；R>1 时叠加中位数线与
  IQR 半透明带（ECharts 双线 + area 堆叠实现）。x 范围为 2..当前 k，
  随运行向右延伸。
- **K_max 与 K_select 的关系（独立，勿耦合）**：K_max 是模拟的推进
  范围（内存/时间预算的函数），K_select 只是观察游标，**不需要也不
  应该约束 K_max ≤ K_select**。K_select ≤ 当前进度 → 曲线 2 显示模拟
  密度；K_select > 当前进度或 > K_max → 曲线 2 仅显示理论曲线并提示
  "当前 K 超出模拟进度（K_max = …）"；进度推进超过 K_select 后叠加
  自动出现。K_max 在启动时显示即完成注明。
- **N 变化 → 自动停止并清空全部数据与叠加**（点积分布、max 轨迹、
  直方图均严格以 N 为参数，跨 N 混池无统计意义），随后按新 N 重算
  并显示 K_max。**单双侧变化同理**（max ρ 与 max|ρ|、ρ 与 |ρ| 直方图
  互相不可换算，必须清空）。K 滑块变化不影响模拟（纯视图游标）。

## 7. 边界情况与精度

- **K=2 起步**：轨迹从 K=2 开始，此时 max ρ 即单对样本，直方图早期
  噪声大、随 M=K(K-1)/2 增长迅速平滑。
- **Float32**：点积累加在 N ≤ 8192 下误差 ~10⁻⁴ 量级，对验证图无影响；
  内存是选择 Float32 的主因。
- **分配失败兜底**：见 §4.3（K_max 减半重试，最多 3 次；probe 首块
  即失败回退 256 MB）。
- **提前停止**：任意时刻停止，已得到的 K 范围内结果完全有效；
  已完成批次的池化统计不受影响。
- **重复运行**：参数（N/双侧/种子）变化等同重置：清空全部池化统计
  与叠加；未变时「追加一批」继续累积。**R_batch 变化无需清空**——
  池化按轨迹曲线累积，各批轨迹数可以不同，已累积数据仍然有效。
- **跨批一致性**：固定种子下 RNG 流连续，"一批 16 条"与"两批各 8 条"
  的池化 maxPerRun 集合完全一致（node 自检覆盖，见 §9）。
- **K_select 超出进度/K_max**：曲线 2 无模拟叠加（给提示），理论曲线
  不受影响；曲线 1 的模拟中位数带只画到当前进度为止。

## 8. 文件结构

- **新增 `js/montecarlo.js`**：纯计算层，无 DOM 依赖（与 theory.js 同风格）：
  mulberry32、Box–Muller、向量采样、直方图/最大值累积器、
  `createSimulation({N, KMax, R, twoSided, seed})` 返回 generator

  阶梯线/轨迹带渲染、清除逻辑。

- 不引入新依赖。

## 9. 测试与验收

1. **node 自检**（montecarlo.js 可直接跑）：
   - 固定种子，N=1024、R=64 跑到 K=200：直方图均值 |mean| < 0.002；
     直方图各槽高度与 `Theory.pairDotDensity` 形状吻合（目视/粗 χ²）；
   - 跨轨迹中位数在若干 K 处与 `Theory.maxDotQuantileBeta(0.5, …)`
     相对偏差 < 10%（烟测容差；R=64 时统计涨落本身 ~1%）；
   - 暂停/继续等价性：连续跑 vs 每片 5 ms 分片跑，固定种子下
     maxPerRun 完全一致；
   - 分批池化等价性：固定种子下"一批 16 条"与"两批各 8 条"的池化
     maxPerRun 集合一致，直方图 count 总和一致；
   - 列切片密度重建：固定种子 R=256、K=50 的列样本直方图与
     `Theory.maxDotDensityBeta` 峰值位置偏差 < 1 个 bin 宽；
   - 预算函数：probe 峰值 → min(峰值×0.7, 2 GB) 及 256 MB 兜底的
     分支正确（probe 本身只在浏览器执行，函数纯逻辑可单测）。
2. **浏览器人工验收**：默认 (N=1024, R=16) 启动显示 K 上限与内存；
   运行中曲线持续刷新、状态栏更新；暂停/继续/停止行为正确；
   直方图最终贴合绿线，轨迹中位数带贴合蓝线。
