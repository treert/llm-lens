# 蒙特卡洛模拟验证 · 设计文档（v3：顺序轨迹流）

在现有理论曲线（F^M / Gumbel / 一阶近似）之上叠加真实随机采样结果，
直观验证理论曲线，并把 README §5.3 讨论的近似误差变成可见现象。

## 0. 架构演进

- **v1**（T 次独立试验）：总成本 $T \cdot K^2 N / 2$，只覆盖当前一个 K。否决。
- **v2**（R 条锁步并行批）：每对点积只算一次，但 R 条轨迹同时存活，
  内存 $4R K_{\max} N$ 被放大 R 倍；且"批"带来额外 UI 复杂度。否决。
- **v3（现行）**：**顺序逐条轨迹**。一条轨迹从 K=2 推进到 K_max，
  跑完曲线入池、向量释放，再开下一条。关键认识：算法唯一不可约的
  内存单位是**单条轨迹**（第 i+1 个向量要与同轨迹之前 i 个点乘，
  历史向量必须共存），内存峰值仅 $4 K_{\max} N$（MB 级）。

v3 的优势：

- 内存最小化，K_max 不再受 R 摊薄，反而放大（N=1024 时 ~2200）；
- 第一条轨迹跑完（<1 s 级）即得全 K 范围曲线，反馈更快；
- 每条轨迹独立 RNG 子流（seed 与轨迹全局序号派生），确定性与
  推进节奏无关；
- UI 无"批"概念：开始 / 暂停 / 继续 / 重置 + 自动追加（默认开）+
  手动「追加一条」。

## 1. 目标与统计映射（核心）

流式运行产生三类累积量，**各自验证的对象不同，不能混淆**：

| 累积量 | 收敛/对比对象 | 落在哪张图 |
|---|---|---|
| ① 点积槽位直方图（全部 $\rho_{ij}$） | **单对 beta 密度**（曲线 2 **绿线**，引理 6.1） | 曲线 2 阶梯线叠加 |
| ② 每轨迹运行最大值曲线 $\max_{i<j\le K}\rho_{ij}$ | 曲线 1 的三条**中位数**理论线；任意 K 处的 **max ρ 密度**（蓝线） | 曲线 1 中位数/IQR 带；曲线 2 按需密度重建 |
| ③ 点积总和与总数 | sanity 指标：均值应 ≈ 0（对称性） | 状态栏文字 |

要点与推论：

- **① 的点积直方图验证的是绿线（单对 beta）**，它与 K 无关，全程累加
  计数即可，**无需按 K 分别保存**。
- **② 的曲线池不合并**：每条轨迹的完整曲线（每个 K 一个运行最大值）
  原样保留（$4(K_{\max}+1)$ ≈ 9 KB/条，千条 ~9 MB）。所有聚合都在
  显示时**按列（固定 K）现算**：
  - 曲线 1：对该 K 列的 R 个样本取**中位数、Q1、Q3**（不是均值——
    理论线是中位数口径）；
  - 曲线 2：K_select 列的 R 个样本按需分 bin / KDE 重建 max ρ 密度
    （R<8 不显示；8≤R<32 阶梯直方图；R≥32 KDE，Silverman 带宽
    $h=0.9\min(\hat\sigma,\,\mathrm{IQR}/1.34)\,R^{-1/5}$）。
- **"第 K 步全体点积的均值/中位数"不随 K 变化**：每对 $\rho_{ij}$ 的边缘
  分布恒为零对称 beta，均值、中位数恒 ≈ 0，画出来是平线，**不画**；
  均值仅作 ③ 的 sanity 显示。随 K 增长的是**极值**，故 ② 记录运行最大值。
- **中位数估计涨落** ~ $1.25\sigma/\sqrt{R}$（max ρ 相对散布 ~ 5%）：
  R=16 约 ±1.7%，R=64 约 ±0.9%，R=256 约 ±0.4%；理论线间差距
  5%~25%，R=16 已足以判别，自动追加下 R 持续增长、涨落单调收窄。
- 大 K 端模拟中位数可能略高于 F^M 线：点对实为两两独立而非相互独立，
  这是 F^M 独立性近似的真实误差（README §5.3），属预期现象。

## 2. 流式算法（单条轨迹）

```
状态：V = Float32Array(K_max × N)     // 本轨迹向量（跑完即释放）
      arr = Float32Array(K_max + 1)   // 本轨迹运行最大值曲线
      hist[B+2] = {sum, count}        // 全局点积槽位数组，两端开口
      sumAll, cntAll                  // 全局点积和与计数
      maxRuns[]，runsTotal            // 已完成轨迹曲线池

for k = 2 .. K_max:
  v = 采样单位向量(N) → V[k]          // 高斯归一化，见 §3
  m = -inf
  for j = 1 .. k-1:
    ρ = dot(v, V[j])
    更新 hist(ρ)；sumAll += ρ；cntAll++
    m = max(m, twoSided ? |ρ| : ρ)
  arr[k] = max(arr[k-1], m)
  （每完成一个向量 yield 一次，由驱动器按时间片调度）

轨迹结束：arr 入池 maxRuns、runsTotal++、V 释放
```

- **generator + 时间片**：`nextTrajectory()` 为 generator，驱动器循环
  `next()` 直到单片 ~30 ms 预算耗尽后 `setTimeout(0)` 让出。暂停 =
  停止调度（闭包状态保留）；继续 = 恢复调度。
- **进行中轨迹的部分曲线也参与聚合**：列 K ≤ current.k 时计入样本。
- 双侧模式：直方图累积 $|\rho|$（对应曲线 2 的"×2 折叠"绿线），
  运行最大值取 $\max|\rho|$。

## 3. 采样原理

- **球面均匀采样：高斯归一化**。$x = z/\|z\|$，$z \sim \mathcal N(0, I_N)$。
  多元标准正态各向同性（旋转不变），方向在 $S^{N-1}$ 上均匀。
- 均匀 RNG：**mulberry32**；**每条轨迹独立子流**：
  `seed_traj = seed + (轨迹全局序号) × 0x9E3779B9 (mod 2³²)`，
  因此轨迹结果与推进节奏（连跑 / 分次 / 暂停）无关，固定种子全过程确定。
- 高斯 RNG：**Box–Muller**，缓存 $\sin$ 支路复用。

## 4. 数据结构

### 4.1 点积槽位直方图（hist）

- 范围按 $(N, \text{双侧})$ 固定：单侧 $[-8\sigma, 8\sigma]$、双侧
  $[0, 8\sigma]$（$\sigma = 1/\sqrt N$），512 个等宽内槽 + 首尾开口槽；
  每槽 `{sum, count}`。绘图为阶梯线（bin 中心展开为平顶点对），
  高度 = count / (cntAll × 槽宽)。

### 4.2 轨迹曲线池（maxRuns）

- 每条完成轨迹一条 `Float32Array(K_max + 1)`，只入池不合并；
  进行中轨迹 `{ arr, k }` 挂在 `pool.current`，部分曲线同样可读。
- 一池两用：按"列"（固定 K，跨轨迹）聚合给曲线 1 中位数/IQR、
  给曲线 2 按需密度重建；不需要任何按 K 预存的结构。

### 4.3 预算 → K_max（启动时计算并显示）

内存约束只剩单条轨迹：$4 K_{\max} N$ 字节；运算预算 $C_{\text{ops}}$
决定单条耗时，**UI 提供四档"单条时长"**（切换等同重置，因曲线长度随
K_max 变化）：快速 $2.5\times10^8$ / 标准 $2.5\times10^9$（默认）/
宽覆盖 $10^{10}$ / 超宽覆盖 $4\times10^{10}$ 次乘加：

$$K_{\max} = \min\Bigl\lfloor
  \frac{B_{\text{mem}}}{4N},\;
  \sqrt{\frac{2C_{\text{ops}}}{N}},\;
  N^2 \Bigr\rfloor,\qquad K_{\max} \ge 2$$

默认下 K_max 被**运算预算**封顶（单条轨迹内存仅 MB 级，内存永不沾边），
标准档示例：

| N | K_max（标准档） | 单条内存 | 单条估算耗时* |
|---|---|---|---|
| 1024 | ≈2209 | ≈8.6 MB | ~3.5 s |
| 4096 | ≈1104 | ≈17 MB | ~3.5 s |
| 8192 | ≈781 | ≈25 MB | ~3.5 s |

档位对 K_max 的影响（N=1024）：快速 ≈698（~0.4 s/条）→ 标准 ≈2209
（~3.5 s）→ 宽覆盖 ≈4420（~14 s）→ 超宽覆盖 ≈8838（~55 s）。
档位是"K 覆盖宽度 vs R 积累速度"的权衡：宽档覆盖大 K，但中位数涨落
收窄变慢。

\* 按 ~0.7×10⁹ 次乘加/秒实测；首条轨迹实测校准并动态显示本条 ETA。

**JS 内存限制与分配策略**：

- 单个 ArrayBuffer 上限 ~2 GB（Chrome/Firefox 64 位），单条轨迹
  一块 `Float32Array(K_max × N)` 最大仅几十 MB，永不触碰；
- 分配包 try/catch，失败则 K_max 减半重试（最多 3 次）。

**首次运行实测预算（probe）**：2 GB 只是名义上限，真实预算在**首次点击
「开始模拟」时实测**（每会话一次，结果缓存）：

1. 以 64 MB 步长渐进分配 ArrayBuffer，**每 4 KB 页写 1 字节**——未触碰
   的页是惰性提交的，只分配不写测不出真实可提交内存；
2. 分配失败或达 4 GB 上限时停止，记录峰值并立即全部释放；
3. **真实预算 = min(实测峰值 × 70%, 2 GB)**（30% 余量给页面与 GC）；
4. 控制区显示：`实测可分配 ≈ 1.6 GB → 内存预算 1.1 GB`；
5. 兜底：首个 64 MB 即失败 → 回退 256 MB 并提示。

## 5. 中断 / 继续 / 帧率

- **暂停/继续/重置**：暂停 = 停止调度（可在轨迹中途）；重置 = 丢弃
  generator 并清空全部池化数据与图上叠加、中止自动追加。
- **自动追加（默认开）**：一条轨迹完成后立即开始下一条，R 单调增长，
  直到用户暂停/重置或参数变更。关闭时跑完一条停下，按钮变为
  「追加一条」供手动逐条推进。
- **帧率控制**：图表重绘节流至 ~4 fps；状态栏每条/每片更新：
  `运行中 · 第 8 条轨迹 · K=1740/2209 · 已完成 R=7 · 内存 8.7 MB
  （向量 8.6 MB + 曲线池 69.1 KB） · 页面堆 54.5 MB · 本条已用
  1.7 s · 剩余 ≈ 1 s`。其中**内存为实时精确账目**（进行中轨迹向量
  缓冲 + 曲线池 + 直方图，`poolMemoryBytes` 计算），"页面堆"为
  `performance.memory.usedJSHeapSize`（Chrome 可用，含页面全部开销，
  仅作参考）。

## 6. UI 集成

控制区：「开始模拟/追加一条」「暂停/继续」「重置」按钮 + 单条时长
四档（切换等同重置）+ 自动追加（默认勾选）+ 固定种子（可选）。
无轨迹数控件。

- 启动时按 §4.3 显示：`K 上限 ≈ 2,209（每条轨迹内存 ≈ 8.6 MB）`；
  状态栏另显示 `累计轨迹 R=…（中位数涨落 ≈ ±x%）` 与点积均值。
- **曲线 2**：两个模拟叠加层。① 点积阶梯直方图（灰），贴合绿线；
  ② K_select 处 max ρ 模拟密度（紫），按列现算，滑动 K 即时切换。
- **曲线 1**：R=1 时叠加单条原始"破纪录"路径；R≥2 叠加中位数线，
  R≥8 再加 IQR 半透明带（**闭合多边形**：正向 q1 + 反向 q3；ECharts
  堆叠面积在 log 轴下会填充到 y=0 而非下边界，不可用）。
- **K_max 与 K_select 的关系（独立，勿耦合）**：K_max 是单条轨迹的
  长度目标（运算预算的函数），K_select 只是观察游标。K_select ≤ 已覆盖
  K → 曲线 2 显示模拟密度；否则仅理论曲线并提示"当前 K 超出模拟进度"。
- **N 变化 → 自动停止并清空全部数据与叠加**（数据严格以 N 为参数）；
  单双侧变化同理（max ρ 与 max|ρ|、ρ 与 |ρ| 直方图互相不可换算）。
  K 滑块变化不影响模拟（纯视图游标）。

## 7. 边界情况与精度

- **K=2 起步**：此时 max ρ 即单对样本；直方图早期噪声大，随
  M=K(K-1)/2 与轨迹数增长迅速平滑。
- **Float32**：点积累加在 N ≤ 8192 下误差 ~10⁻⁴ 量级，对验证图无影响；
  内存是选择 Float32 的主因。
- **任意时刻停止**：已完成轨迹的池化统计完全有效。
- **顺序追加等价性**：轨迹独立子流保证"连跑 16 条"与"8+8 分两次"的
  池化 maxRuns 完全一致（node 自检覆盖，见 §9）。
- **分配失败兜底**：见 §4.3（K_max 减半重试，最多 3 次；probe 首块
  即失败回退 256 MB）。

## 8. 文件结构

- **`js/montecarlo.js`**：纯计算层，无 DOM 依赖（与 theory.js 同风格）：
  mulberry32、Box–Muller、向量采样、直方图/列聚合/KDE、
  `createSession({N, KMax, twoSided, seed})` → `{ pool, nextTrajectory() }`。
  导出兼容 node（`typeof window !== 'undefined' ? window : globalThis`）。
- **`js/app.js`**：控件与状态栏、时间片驱动器（30 ms 预算 + 4 fps 节流）、
  叠加渲染、清除逻辑；理论曲线数据按 $(N, K, \text{双侧})$ 缓存，
  MC 运行期只重算叠加层。
- **`index.html`**：控制区按钮/复选框，引入 `montecarlo.js`。
- **`test/mc-selftest.js`**：node 自检（无框架，直接断言）。
- 不引入新依赖。

## 9. 测试与验收

1. **node 自检**（`node test/mc-selftest.js`）：
   - 预算函数分支（兜底/×0.7/封顶 2GB）与 computeKMax 两例；
   - K=2、单侧、256 条轨迹：中位数 |med| < 0.01（精确值 0）；
   - N=1024、64 条轨迹：点积均值 |mean| < 0.002；K=10/50/200 跨轨迹
     中位数与 `Theory.maxDotQuantileBeta(0.5, …)` 相对偏差 < 10%；
   - 固定种子两次运行 maxRuns 完全一致；
   - 顺序追加等价：16 条 ≡ 8+8；
   - 进行中轨迹部分曲线：列覆盖规则正确（coveredK / columnValues）；
   - 列切片密度重建：R=256、K=50 直方图峰值与
     `Theory.maxDotDensityBeta` 偏差 < 1 个 bin；
   - 双侧：列样本全部 ≥ 0，中位数偏差 < 10%。
2. **浏览器人工验收**：默认 (N=1024) 启动显示 K 上限与单条内存；
   自动追加下 R 持续增长、曲线持续刷新；暂停/继续/重置正确；
   直方图贴合绿线，中位数带贴合蓝线；N 切换自动清空。
