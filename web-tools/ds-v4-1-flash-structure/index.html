LLM LENS · 模型结构笔记

DeepSeek-V4.1-Flash 结构说明

552B 主干参数的原生多模态 MoE 模型:非对称 Causal Encoder–Decoder(CED)+ 压缩稀疏注意力 CSA² + FP4 KV Cache + Hyper-Connections + Engram 参数化记忆。 核心收益:Prefill 计算量近乎减半、Global KV Cache 从 3514 → 890 Bytes/token(降低约 75%)。

✅ 已与官方开源发布(HuggingFace)逐项核对: config.json、inference/model.py / engram.py / vision.py、 model.safetensors.index.json(96,085 张量 / 475.24 GiB / 48 分片,全部一致); 并补充了阅读推理代码才能确认的实现级细节。

1总体架构

模型类型 DeepseekV41ForCausalLM,由语言主干(40 层)、ViT 视觉塔(32 层)、 aligner 与 3 层 DSpark MTP 草稿层组成。语言主干被切成两段: L0–L19 是 Causal Encoder,L20–L39 是 Decoder——这是理解全模型所有设计的出发点。

3CED:因果编码器—解码器

传统 40 层 Decoder-only 模型,Prefill 时每个 Prompt token 都要完整通过 40 层,每层还要自产 KV。 CED 的做法:Decoder 的 global KV 不由各层自己的隐状态生成,而是统一由 Encoder 末层输出 H₂₀ 经 L20 的 compressor 投影得到:

C = H₂₀ · WKV  (checkpoint 中只有 L20 一份 compressor 权重,全 Decoder 共享一份缓存)

L21–L39 没有 compressor / indexer 权重,global KV 纯读 L20 的缓存,层间差异由各自的 Q 承担 (存储只需一份,这正是 890 B/token 里 decoder 只占 356 B 的原因)。 于是长度为 S 的 Prompt 只需完整跑前 20 层 Encoder; 只有 Prompt 末尾窗口内的 token 需要继续跑 Decoder 的 SWA Bounded Replay 来构建局部 SWA KV (最后一个 token 走完 40 层,产出第一个回答 token)。

  • Prefill:主体计算 ≈ 20/40 = 一半,官方口径每 token 激活 8B 参数;
  • Decode:新 token 仍要过 Encoder 产 KV 增量、再过 20 层 Decoder,即完整 40 层(16B/token),CED 不减半 Decode;
  • 上下文 4K → 1M(256 倍),单 token Decode FLOPs 只增约 25%(解码计算不再随上下文线性增长;端到端延迟还受 KV 读取、通信、调度影响)。
  • SWA Bounded Replay 的另一半用途:decoder 各层的 SWA KV 只能由本层隐状态现算,但窗口只有 128 槽、大小与上下文无关——于是会话挂起/迁移/换 checkpoint 时,SWA KV 直接丢弃不持久化;恢复时只需把最近 128 个 token 重新过一遍 Decoder(replay),40 层滑窗缓存即重建完毕。因此它不占随长度增长的持久化存储(持久化 KV 由此降到上一代 ≈ 1/8)。背后的判据:能不能便宜地重算,决定了要不要存——SWA 能(128 token 重放即可),global KV 不能(重算要把全部历史重跑一遍 Encoder),所以后者才需要 FP4 + 跨层共享这些极限压缩手段。

4Latent Attention 与 CSA²

4.1 核心认知:SWA × CSA²,一次注意力 = 两路 KV 拼接

SWA 与 CSA² 不是两种互斥的注意力模式,而是每次注意力同时存在的两路 KV 来源: L2–L39 的每个注意力层,本层自产的滑窗 KV 与组内共享的压缩检索 KV 拼接后,由 Q 统一打分、 同一个 softmax 归一(分母外加 attn_sink 一项)、统一加权求和——一次 sparse_attn 完成:

SWA 分支(局部,细)压缩检索分支(全局,粗,即 CSA² 管的就是它)
覆盖范围最近 128 个 token全部历史中检索出的 Top-512 个压缩位置
KV 来源本层现算:wkv(5120→512),40 层各自独立权重、独立缓存仅组首 Full 层(L2/L8/L14/L20)的 compressor 产出,组内其余层纯读缓存
精度FP8FP4(main KV 288 B/条 + index K 68 B/条)
缓存形态每层 128 槽环形缓冲(40 层 ≈ 2.6 MB/序列,与上下文长度无关;挂起时丢弃,恢复时 replay 最近 128 token 重建)随长度增长的全局缓存(合计 890 B/token,推导见 §6)
L0/L1/MTP有(是唯一分支,故称"纯 SWA 层")无(compress_ratio=0,整支跳过)

即每个 query 最多看 128 + 512 = 640 个位置:近处是"本层视角"的细粒度原始 KV, 远处是"组首/encoder 视角"的粗粒度压缩 latent。两路位置有重叠——最近 128 个 token 在两路各有一份 副本(投影不同、不去重,都进同一个 softmax);唯一的可见性限制是组级因果掩码:一个压缩组要等 query 越过组内最后一个 token 才对它可见。

控制这条全局分支粒度的旋钮是逐层配置的 compress_ratios(43 项,含 3 个 MTP)。 它身兼两职:全局分支的开关 + 源层的 token 合并比:

取值层含义
0L0/L1/MTP全局分支整支关闭,纯 SWA。开头两层隐状态近词嵌入、上下文未整合,全局检索没有意义;局部的交给滑窗 + Engram(L1),还省了 indexer 计算与 Top-512 读取的开销;MTP 草稿天然只看局部
2L2–L19encoder 组:源层 compressor 把 2 个 token 池化成 1 条 latent,条目数减半(浅层全局注意力容忍度高)
1L20–L39decoder 组:逐 token 一条、不合并(wgate 退化为无,纯投影)——最接近输出的 20 层唯一的长程记忆,不再压序列维;压缩靠通道(5120→512)、层共享(20→1)、FP4 三个维度承担

连带影响:压缩缓存条目数 = S/m;压缩条目的 RoPE 取组首 token 位置(第 j 组取 j×m);indexer 打分粒度 = 压缩条目; r=0 的层禁用 YaRN(θ=10000),r>0 的层整层用 θ=160000 + YaRN。注意 m 与 latent attention(通道压缩)、 CSA² 层间共享是三个独立旋钮,别混为一谈。

边界细节(奇数长度怎么办):m>1 时末尾凑不满一组的 token 不硬压——余数落进 compressor 的 kv_state/score_state 状态缓冲,等下一个 token 凑满再池化(组边界是纯位置性的, 一条 latent 可以横跨 prompt/生成边界,如"prompt 末 token + 首个生成 token")。 落单期间它不进压缩缓存、不参与全局分支检索,但必然躺在每层的 SWA 窗内:组最晚在下一个 token 到达时凑满, 而滑窗要 128 步后才把它覆盖——两套缓存有 ~127 步的交接重叠带,任何时刻都不存在"谁都看不见"的 token (新靠 SWA、老靠压缩缓存,交接期两路都在)。

4.2 单层结构:latent attention(layers.N.attn.*)

  • Q 低秩:wq_a(5120→1280)→ q_norm → wq_b(1280→32768 = 64×512);
  • 单 KV 头:wkv(5120→512)→ kv_norm;每个位置只有一个 512 维 latent,64 头共享,K 与 V 是同一个向量;
  • RoPE 只加在末 64 维(qk_rope_head_dim),前 448 维是 NoPE;
  • attn_sink:64 维逐头 sink logit(softmax 分母多一项);
  • 输出投影分组低秩:输出 reshape 成 8 组(每组 8 头×512=4096),wo_a 块对角(4096→1024)→ wo_b(8192→5120);输出后对 rope 尾维做逆旋转(V 向量带着 RoPE);wo_a 在 checkpoint 是 FP8,官方 convert.py 反量化成 bf16 后按块对角 einsum 使用;
  • RoPE 每层只有一组频率:compress_ratio=0 的层(L0/L1/MTP)禁用 YaRN、用基础 rope_theta=10000;compress_ratio>0 的层(L2–L39)整层(Q、SWA 滑窗 KV、压缩 KV 共用)用 compress_rope_theta=160000 + YaRN——名字里的 "compress" 有误导性,压缩 KV 的"位置间隔更大"是靠旋转位置取组首 token(第 j 组取位置 j×m)体现的,不是单独的 theta。

4.3 CSA²:压缩检索分支的跨层复用(Full / Reindex / Reuse)

每个注意力层仍然计算自己的 Main Query 和 SWA(128)KV,但全局稀疏注意力所用的 main KV、indexer K、Top-K 索引可以跨层共享。三种静态模式逐层指定:

模式做什么本模型对应层
Full自产 main KV;indexer K 由 main KV 投影;跑 indexer 产 Top-512(唯一能产出可复用 cache 的模式)kv_source_layer_ids = {2, 8, 14, 20}
Reindexmain KV 与 indexer K 复用前序层,用本层 indexer Q 重算 Top-K{24, 28, 32, 36}
Reusemain KV、indexer K、Top-K 全复用,不跑 indexer其余 30 层

Encoder 侧:18 个 CSA² 层(L2–L19)分 3 组,每组一个 Full 层,压缩率 m=2。 Decoder 侧:仅 L20 为 Full(其 compressor 吃第 20 层注意力子层输入,即 CED 公式的实现), 4 个 Reindex + 15 个 Reuse,m=1。与上一代 CSA 相比,CSA² 删掉了压缩窗口重叠、 压缩阶段的绝对位置编码,indexer K 直接从 main KV 投影,并把 KV 共享与 Top-K 复用解耦。

4.4 分层稀疏索引(Hierarchical Sparse Indexer)

indexer(32 头 × 128 维:indexer.wq_b 1280→4096、wk 512→128、k_norm、weights_proj 5120→32) 若每次扫全部百万 token 自身也会成为瓶颈。因此 Decoder 的第一个 Full 层(L20)扫描全部可见位置时, 除了自己的 Top-512,还按 8 token 一块取最大 indexer score,选出得分最高的 2048 块 = 16,384 个位置 组成共享候选池(candidate_source_layer=20)。后续 Reindex 层只在候选池内打分选 Top-512—— 索引计算量从随上下文线性增长变成近似常数。 实现上,块得分取块内最大 indexer score;含最新位置的未满块会被强制保留(pin 为 +inf), 防止它因位置不满而被老的满块挤出候选池。

4.5 FP4 Main KV Cache 与 compressor

  • main KV / 压缩 latent:FP4 E2M1,每 16 通道一个 E4M3 scale(MXFP4),无第二级全局 scale,在 RoPE 之后量化;
  • indexer K:FP4 E2M1,每 32 通道一个 E8M0 scale(纯 2 的幂,只用于 Top-K 排序);
  • SWA KV 保留 FP8(对整个 post-RoPE 向量量化,RoPE 尾维在内);"长程粗、局部细";indexer Q 推理时同样量化到 FP4;
  • 数值依据:归一化后 512 维 latent 的 L2 范数上限 √512,训练期实测最大幅值 ≈ 10,不需要全局 scale;
  • SWA Bounded Replay:只 replay 最近 128 个 token,把 SWA 截断在该段内,使 SWA KV 从持久化 cache 中移除(持久化 KV 降到上一代 ≈ 1/8)。

实现上,compressor 的工作方式是:m>1 的层(L2–L19)用 compressor.wkv/wgate(fp32)把 m 个连续 token 经学习到的 softmax 门控池化成一个 latent;m=1 的层(L20–L39)退化为纯投影(bf16,无 wgate)。 compressor 输出的是未加 RoPE 的 latent:indexer 先拿它投影出 index K 写入缓存,然后才对 latent 施加 RoPE、 量化 FP4 写入 main KV 缓存——同一份存储先读后写,两种用途各取所需形态。

5位置编码:部分维 RoPE + 分频段 YaRN

5.1 施加范围:512 维里只有末 64 维旋转

  • head_dim 512 = 448 维 NoPE + 64 维 RoPE(qk_rope_head_dim):Q(64 头)与共享 KV latent 都只旋转末 64 维,前 448 维是纯内容维——位置信号与内容信号在通道上分离;
  • 旋转方式:相邻两维配成复数,乘位置相位 ei·p·θᵢ,共 32 个频率 θi = base−2i/64;
  • indexer 的 Q/K(128 维)同样只旋尾 64 维,并与主注意力共用同一套频率表(indexer.freqs_cis = self.freqs_cis)——保证检索打分与正式注意力的位置口径一致;
  • 输出端有逆旋转:V(= KV latent 本身)带着 RoPE 相位,加权求和后对输出尾 64 维乘共轭相位还原——残差流中的表示因此不含位置相位,缓存也能保持统一的旋转形态(apply_rotary_emb(o, freqs, inverse=True))。

5.2 频率配置:每层一组,共两档

层base θYaRN理由
L0 / L1 / MTP(compress_ratio=0)10,000禁用只看 128 滑窗,没有长程外推需求
L2–L39(compress_ratio>0)160,000启用(factor 16,原始 65,536)全局分支要面对 1M 上下文;整层(Q、SWA KV、压缩 KV)共用这一组频率

压缩条目的旋转位置取组首 token(第 j 组取位置 j×m,"一个 latent 代表组内第一个 token")—— 压缩 KV 的"位置间隔更大"由此体现,而非单独的 θ;config 里 compress_rope_theta 的名字有误导性, 它实际是"所有带压缩分支的层的 θ"。

5.3 YaRN:按频段分别插值(65,536 → 1,048,576)

对 32 个频率按"该维在训练长度 65,536 内转几圈"分三段(precompute_freqs_cis 的 original_seq_len > 0 分支):

频段判据(训练长度内圈数)处理
高频> 32 圈(beta_fast=32)频率不动——波长远小于训练长度,没有外推问题,保住局部位置区分度
低频< 1 圈(beta_slow=1)频率 ÷ 16——一圈都没转完的纯外推段,直接位置插值
中间1–32 圈线性 ramp 渐变过渡(两段之间不平滑切换会引入伪周期)

注意:本模型没有采用原版 YaRN 论文的 attention 温度缩放——softmax_scale = 512−0.5 固定不变, 温度补偿可能已在训练中吸收。

5.4 视觉塔:独立的 2D RoPE

ViT 用二维 RoPE:h、w 两个方向各有一套位置频率(θ=10,000),双向注意力; 配对方式是"前后半配对"(chunk 两半)而非语言侧的"相邻两维配对",两套实现各自独立 (vision.py 的 apply_rotary vs model.py 的 apply_rotary_emb)。

7Hyper-Connections(Single-Pass mHC)

残差流不是单向量,而是 hc_mult=4 份并行副本(layers.N.hc_{attn,ffn}_{fn,base,scale},fp32):

  • 每个子层前后各一次可学习混合:hc_pre 把 4 份压成子层输入,hc_post 把输出扩回 4 份,并经 comb 矩阵(Sinkhorn 20 次迭代成双随机)混入残差;
  • 混合系数由流本身算出:hc_fn(24×20480)+ hc_base(24)+ hc_scale(3);24 = (2 + hc_mult) × hc_mult:pre(4)+ post(4)+ comb(16);投影前对整个展平的 4×5120 流逐 token 算一个 RMS 归一化统计量(不是逐副本);
  • Single-Pass:子层算出的系数给下一个子层用(输入混合改用上一层产出的系数),解除"先算系数再混合"的数据依赖:
    Xl+1 = Bl·Xl + Cl·Fl(Al−1·Xl)
  • 部署期融成 Mega-mHC kernel(残差更新 + 输入混合 + 系数预测 + Pre-Norm + FP8 转换),激活内存流量从 (4n+4)d 降到 (2n+2)d(理论下界,n=4),约降一半。

8Engram:参数化 n-gram 记忆

对固定短语、实体名、代码模式等高度重复的局部知识,不必让 Transformer 每次用多层 attention + MoE 重新推导——直接拿最近几个 token 去巨型可训练 embedding 表里查。 MoE 是 Conditional Computation(按隐状态选专家),Engram 是 Conditional Memory (按 n-gram 查记忆);不是 RAG,是端到端训练的内部记忆表。

一个准确的心智模型:Engram ≈ 在 L1、L14 两个 Block 前面各"硬插"了一个记忆层。 代码上就是 h = engram(h, hash_ids) 之后原样 h = block(h)——L1/L14 本身是 完全标准的 Block(latent attention + MoE + HC),结构与权重上零改动(Block.forward 里没有 任何 engram 逻辑,调用点在 Transformer 主循环);当然,该层及其后的所有计算都运行在注入后的残差流上 (这正是目的——包括该 Block 用注入后的 h 算出的 HC 混合系数)。 这个插入层与正常 Block 的差别只在:输入只依赖当前位置最近 3 个 token 的 id(哈希查表, 不读隐状态)、计算量恒定(24 次 lookup + 一次投影,不随上下文增长)、写入是纯加法 (h += gate × value)。上下文感知只剩 gate 一个标量;图像 token 处 gate=0 直接跳过。

7.1 计算流程(五步)

  1. Tokenizer 压缩:原始 token id 经规范化管道映射为压缩 id(只用于构造查询键,不改模型 tokenizer);管道为 NFKC → NFD → 去口音 → 小写 → 空白合并(含"单空格 token"哨兵保护),129,280 个 token 收敛出 99,092 个唯一 key(config 的 engram_compressed_vocab_size,哈希乘子由它导出,不匹配会静默重哈希整张表);
  2. 后缀 n-gram:当前位置取最近 token 构造 2/3/4-gram(不含未来 token,保持因果;n-gram 不跨越图像 span——遇到 dead token 即截断填 pad);
  3. 多头哈希:每种阶数 8 个 hash head,共 24 次 lookup,拼接出 24×256 = 6144 维——碰撞在 8 个独立 head 下同时撞上的概率极低;哈希为"奇数乘子 × 压缩 id 后 XOR 滚动"(每层的乘子由 seed=10007×layer_id 的 RNG 生成),每个 (阶数, head) 占有自己质数大小、互不相交的桶区间(从 1600 万起依次取未用过的质数);
  4. 投影 + 上下文门控:engram.wkv(6144→25600)投出 4 份 HC 副本各自的 key + 1 份共享 value;门控 = sigmoid(signed_sqrt(归一化点积))——n-gram 提供候选记忆,当前隐状态决定写不写;
  5. 门控写入残差流(V4.1 删除了原论文门控后的短因果卷积);图像 token 不参与(engram_mask 关门)。

9MoE 与路由

  • 每层 ffn.gate.weight(384×5120)+ gate.bias + gate.bias_vl(fp32,noaux_tc 校正;图像 span 内 token 用 bias_vl);

10DSpark MTP(推测解码草稿)

  • num_nextn_predict_layers=3,前缀 mtp.0/1/2(layer_id 40/41/42),每层是完整 Block(注意力 + MoE),embed/head 与主干共享;

11视觉塔(ViT + aligner)

11.1 结构参数

  • vision.*:32 层 ViT(hidden 1024、16 头、patch 14 → patch_embed.proj 1024×588),MLP SwiGLU 融合(w1 [5632,1024]、w2 [1024,2816]),标准 pre-norm,bf16 未量化;注意力是双向的并带 2D RoPE(h/w 两个位置频率);patch_embed 与注意力投影带 bias,MLP 的 w1/w2 无 bias;max_image_tokens=1024;

  • image_start/image_end/image_newline:5120 维可学习边界嵌入;image_token_id=129264。

11.2 位置信息如何进入:不是"融进 token",而是"藏在特征里"

这个 ViT 没有经典 ViT 的绝对位置嵌入(patch_embed 是裸 Linear,无任何 additive position embedding)。 位置感经由两个间接渠道形成:

  • ViT 内部的 2D RoPE:只作用于每层注意力的 Q/K(影响 patch 间的关注模式),不改变特征向量的内容基底;
  • aligner 的 3×3 折叠:空间结构被折叠进通道维——每个输出 token 天然对应一个 3×3 patch 块,且按行主序(光栅扫描)排列。

因此进入 LLM 的图像 token 向量不带显式位置编码:图像内部的 2D 结构已由 ViT+aligner 预消化成特征与顺序; 进入文本流后,LLM 的 RoPE 按序列位置统一处理——跨 token 的位置关系归 LLM 管,图像内部的 2D 结构归 ViT 管。

11.3 LLM 侧如何区分图像 token 与文本 token

一切源于 image_processor 准备好的 token_types(文本 = −1,图像 span ≥ 0), 派生出 image_mask,在三处区别对待:

机制对图像 token 的区别对待
Embedding 替换图像 span 位置的 input_ids 全是 image_token_id(129264),embed 后整段被 aligner 特征覆写(merge_image_embeddings);span 边界位置填入可学习的 image_start/end/newline 向量
Engram 关门图像位置 gate=0,不写入 n-gram 记忆;且 n-gram 哈希遇图像 span 即截断(DEAD token),不跨图像组词
MoE 路由换 bias图像 span 内的 token 选专家时用 gate.bias_vl 而非 gate.bias(noaux_tc_for_vl)——图像 token 的专家偏好有独立校正

注意力本身不做特殊掩码:图像 token 在注意力里就是普通位置(占滑窗、进压缩缓存、可被检索)。 多模态的区分全部集中在"入口表示"(替换 embedding)与"路由/记忆"(bias_vl、engram_mask)两处。
