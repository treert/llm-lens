# 并行与分布式:单卡放不下之后

前置:[02-resource-estimation.md](02-resource-estimation.md)、
[10-flashattention.md](10-flashattention.md) §8(Ring Attention)。
目标:理解 TP / PP / DP / EP 四种并行各自切什么、通信代价是什么、
什么互联硬件撑得起,以及我们两台消费卡的现实选择。

## 1. 三个动机

1. **容量**:模型(权重+KV)单卡装不下;
2. **吞吐**:一张卡喂不饱请求量,横向扩;
3. **延迟**:decode 是带宽瓶颈,两张卡的带宽加起来 ≈ 两倍 tok/s。

不同动机对应不同的并行方式,选错方式会让通信开销吃掉全部收益。

## 2. 通信原语速览

| 原语 | 做什么 | 出现在哪 |
|---|---|---|
| All-Reduce | 各卡数据求和,结果人人一份 | TP 每层两次 |
| All-Gather / Reduce-Scatter | 收集 / 求和并分片 | 权重/激活重组 |
| All-to-All | 各卡互发不同数据块 | MoE 专家路由(EP) |
| P2P send/recv | 相邻卡点对点 | PP 流水、Ring Attention |

底层库是 NCCL(NVIDIA),它根据拓扑(NVLink/PCIe/网卡)自动选路径,
但**物理带宽差距无法靠软件弥补**:

| 互联 | 带宽(单向量级) |
|---|---|
| NVLink 4(H100) | ~450 GB/s |
| NVLink 5(B200) | ~900 GB/s |
| PCIe Gen5 x16 | ~50~60 GB/s |
| 消费 GeForce 跨卡 | PCIe,且 P2P 常受限,需经主机内存中转,延迟更高 |

NVLink 与 PCIe 差近 10 倍——这是数据中心卡与消费卡在多卡场景的本质差距。

## 3. TP(张量并行):把矩阵乘拆开

Megatron-LM 的经典切法,以 MLP 的两次投影 $Y = \mathrm{SiLU}(XA)\,B$ 为例:

- **列切** $A = [A_1 | A_2]$:各卡算 $XA_i$,不需要通信;
- **行切** $B$:各卡算部分和 $Y_i$,最后 **All-Reduce** 一次得到完整 $Y$;
- Attention 同理:按头切给各卡,$o$ 投影行切后 All-Reduce。

每个 transformer 层前向共 **2 次 All-Reduce**(attention 输出、MLP 输出)。
通信量 ≈ $2 \times \text{batch tokens} \times d \times 2$ 字节/层——
decode 时 batch 小,通信量其实不大,但**对延迟敏感**:每生成一个 token
就要付几十次往返。NVLink 上几乎无感,PCIe 上则明显拖慢每步。

特点:KV Cache 也随头数切分(各卡只存自己那份头的 KV),所以 TP 同时
扩 KV 容量;但要求层结构规则可切,且卡数通常 ≤8(再通信占比失控)。

## 4. PP(流水线并行):把层拆开

- 按层分段:$L$ 层切成 $P$ 段,每卡一段;
- 激活在段间 P2P 传递,**通信量极小**(每 token 每边界传一个 $d$ 维向量);
- 为了不让后面的卡干等,把 batch 切成 micro-batch 流水起来;
  首尾填充/排空的时间占比即"气泡",micro-batch 越多气泡越小。

特点:对互联要求最低(P2P 走 PCIe 甚至网络都行),适合跨机;
但**不降低单 token 延迟**(反而因流水略有增加),气泡也是纯损耗。
推理场景 PP 用得比训练少,常与 TP 组合(机内 TP、机间 PP)。

## 5. DP(数据并行)与多实例

每个实例完整放一份模型,请求按负载分发:

- 最简单、零通信的吞吐扩展;前提是单卡装得下(我们的 8B/14B 场景);
- vLLM 多实例 + 前置负载均衡即可;DeepSeek 的 attention 层用 DP
  (配 MLA 的 KV 压缩,每卡存全量压缩 KV 也不贵)。
- 注意 DP 不解决容量问题,只解决并发问题。

## 6. EP(专家并行):MoE 的专属切法

MoE 每层有 $E$ 个专家、每 token 只激活 top-$k$ 个:

- 把专家分散到不同卡,token 按路由结果 **All-to-All** 发往对应卡,
  算完再 All-to-All 送回原卡;
- 通信量与激活专家数成正比;**负载均衡**是核心难题(热门专家所在卡
  成为瓶颈),DeepSeek 系列有大量相关工程(冗余专家、偏置调整);
- 对我们的意义:MoE 模型(如 30B-A3B)在**单卡**上就能体现价值——
  权重总量大(Q4 可压到 ~17 GB 内或更小),decode 时每 token 只读
  激活专家的参数(3B 量级),带宽消耗远低于同总参的稠密模型。
  这是资源估算篇案例 D 推荐 MoE 的原因。

## 7. 序列/上下文并行

超长上下文(百万 token)下,单卡连一条序列的 KV 都存不下:

- **Ring Attention**:序列切段分卡,环形 P2P 轮转 K/V,Q 不动,
  靠 online softmax 增量合并,计算与通信 overlap
  (机制见 [10-flashattention.md](10-flashattention.md) §8);
- **Ulysses**:沿头维切,通信模式是 All-to-All;
- 消费卡双人场景基本用不到,了解思想即可。

## 8. 我们的现实推演

两台独立机器(4080、5070 Ti 各 16 GB),无法互联;即使同机双卡:

- **TP=2 跑 32B Q4(18~19 GB)**:权重切两份每卡 ~9.5 GB,KV 也分半,
  容量成立;decode 理论带宽翻倍,但 PCIe + 消费卡 P2P 受限,
  实际加速常见 1.3~1.7×(层数越深通信次数越多);
- 更合适的多卡用法是 **DP/多实例**:每卡各跑一个 8B/14B,接两倍并发;
- 单机单卡场景,MoE 是"免费的多卡体验":30B-A3B Q4 单卡跑,
  等效 decode 带宽消耗 ≈ 3B 稠密模型。

## 9. 选型速查

| 场景 | 推荐 |
|---|---|
| 单卡装得下,提并发 | DP 多实例 |
| 单卡装不下,同机多卡 | TP(有 NVLink 最佳;PCIe 接受 1.3~1.7×) |
| 跨机 | PP 为主,机内 TP |
| 超大 MoE | EP + TP/DP 组合(生产级) |
| 百万级上下文 | Ring/Ulysses 上下文并行 |
| 我们的 16 GB 卡 | 单卡量化;想要大模型选 MoE |

## 10. 小结

- TP 切矩阵(每层 All-Reduce,吃互联)、PP 切层(P2P,怕气泡)、
  DP 复制实例(扩并发)、EP 切专家(MoE 专属,All-to-All);
- 通信带宽决定并行效率:NVLink ≈ 10× PCIe ≈ 消费卡的现实约束;
- 对单人 16 GB 卡用户,并行主要是个"知道边界在哪"的知识:
  量化 + MoE 通常比折腾多卡更划算。
