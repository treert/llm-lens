# 量化:用更低的位宽装下更大的模型

前置:[02-resource-estimation.md](02-resource-estimation.md)(显存与速度账)、
[01-inference-pipeline.md](01-inference-pipeline.md)(decode 是带宽瓶颈)。
目标:理解量化对权重做了什么、为什么 4 bit 几乎不掉点、主流方案
(GGUF K-quant / GPTQ / AWQ / FP8)的区别,以及 KV Cache 量化。

## 1. 为什么量化是推理的第一优化

回忆资源估算篇的两个结论:

- decode 速度 ≈ 带宽 / 权重字节 → 权重砍到 1/4,**速度上限 ×4**;
- 显存 = 权重 + KV + 开销 → 权重砍到 1/4,省下的全给 KV。

量化是极少数**同时改善显存与速度**的手段。代价只是权重的表示精度,
而神经网络恰好对此非常鲁棒——这是整个领域成立的运气基础。

## 2. 量化的数学基础

把一个 FP16 数 $x$ 映射到 $b$ bit 整数 $q$,再近似还原:

$$q = \mathrm{clamp}\big(\mathrm{round}(x/s) + z,\ q_{\min},\ q_{\max}\big),
\qquad \hat{x} = s\,(q - z)$$

- $s$(scale)= 量化步长,由数据的 $[\min, \max]$ 决定:
  $s = (\max - \min) / (2^b - 1)$;
- $z$(zero-point)= 零点偏移;**对称量化**令 $z = 0$($s = \max|x| / 2^{b-1}$),
  计算更省;**非对称量化**贴合偏移分布,精度略高;
- 逐元素误差 $\le s/2$。所以降低误差的核心手段是**缩小每组数据的取值范围**
  → **分组量化**(block-wise):每 32~128 个权重共享一个 scale,
  而不是整张矩阵一个 scale。

为什么神经网络耐量化:

- 严重过参数化,单个权重的扰动会被冗余吸收;
- 训练后的权重分布平滑、近似零均值;
- 推理本身是前向一次过,误差不会像训练那样沿梯度累积。

但有两个已知软肋:**outlier channel**(少数通道的激活/权重量级远超其他,
一个 scale 覆盖不了)和**敏感张量**(embedding、首尾层、注意力输出投影
往往更娇贵)。所有现代量化方案的差别,本质上就是处理这两个软肋的策略不同。

## 3. 主流方案总览

| 方案 | 位宽 | 类型 | 需要校准数据 | 硬件要求 | 典型生态 |
|---|---|---|---|---|---|
| GGUF K-quant | 2~8 bit | 仅权重(W4A16) | 否(纯 round-to-nearest 改进) | 无,CPU/GPU 皆可 | llama.cpp |
| GPTQ | 3~4 bit | 仅权重 | 是(小校准集) | 无(配合 Marlin kernel) | vLLM、AutoGPTQ |
| AWQ | 4 bit | 仅权重 | 是(激活统计) | 无 | vLLM、AutoAWQ |
| FP8 | 8 bit | 权重+激活(W8A8) | 视方案 | Hopper/Ada/Blackwell 原生 | vLLM、SGLang、TRT-LLM |
| SmoothQuant 系 | 8 bit | W8A8 | 是 | INT8 tensor core 普遍存在 | TensorRT 等 |

"仅权重"(weight-only)的意思是:权重以低位存储,**kernel 内即时反量化**
回 FP16 再算。它省显存、省带宽(decode 提速),但计算本身仍是 FP16,
prefill 提速有限。W8A8 则连计算也走低精度 tensor core,**prefill 也提速**,
但要处理激活量化这个更难的问题(§7)。

## 4. GGUF K-quants:分组的艺术

llama.cpp 的 K-quant 系列是纯算法优化(不需要校准数据),靠两级分组:

- 256 个权重组成一个 **superblock**,内含 8 个 32 权重的子块;
- 每个子块有自己的 scale(甚至 min),而子块的 scale 本身再被 superblock
  的 scale 二次量化——**scale 也量化**,元数据开销压到很低;
- 实际位宽:Q4_K ≈ 4.8 bit/权重,Q6_K ≈ 6.56,Q8_0 = 8.5。

**混合档位**(文件名里的 S/M/L):不同张量用不同位宽。以 Q4_K_M 为例,
对质量最敏感的 `attn_v`、`ffn_down` 等投影用 Q6_K,其余用 Q4_K——
这正是 §2"敏感张量"软肋的工程解法,平均 ~4.85 bit 换来接近 Q6 的质量。

经验:Q4_K_M 在多数任务上与 FP16 的差距难以察觉;Q3 开始有可感知损失;
Q2 基本只用于研究。

## 5. GPTQ:用二阶信息做误差补偿

思路:量化不该是"四舍五入完事",而应该问——**量化这一列引入的误差,
能否用尚未量化的其他列调整来抵消?**

- 逐层进行,以小批量校准数据(几百条即可)估计该层输出的 Hessian
  信息(沿 Optimal Brain Quantization 的脉络);
- 逐列量化,每量化一列,就用 Hessian 逆矩阵更新剩余未量化列,
  把误差"推给"后面的列吸收;
- 目标是最小化**该层输出的重构误差**,而非权重本身的舍入误差——
  前者才与模型质量直接相关。

产物通常以 safetensors 分发(vLLM 直接支持),配 Marlin 等专用 kernel
获得接近理论的 decode 加速。

## 6. AWQ:激活感知,保护那 1%

观察:**权重的敏感度不平等**——与大幅值激活相连的极少数权重通道
(约 0.1%~1%)对输出影响巨大。

- 用一小批校准数据统计激活幅值,找出这些 salient channel;
- 不是把它们保留成 FP16(那样 kernel 要处理混合格式,很丑),而是做
  **逐通道缩放**:把 salient 通道的权重放大 $s$ 倍、对应激活等价缩小
  $s$ 倍(数学上输出不变的等价变换),使它们落在量化友好的范围内;
- 这又是本目录反复出现的主题:**用数学等价变换换工程收益**。

AWQ 与 GPTQ 都需要校准数据,质量上互有胜负,生态都成熟;GGUF 胜在
零校准、CPU 友好、文件即下即用。

## 7. FP8 与 W8A8:连计算一起降

FP8 两种格式:**E4M3**(4 位指数 3 位尾数,范围 ±448,用于前向权重/激活)
与 **E5M2**(范围大精度低,多用于梯度)。Hopper 起 tensor core 原生支持,
吞吐为 FP16 的两倍。

- **缩放粒度**:per-tensor(一张量一个 scale,最简单)→ per-channel →
  **block-wise**(DeepSeek-V3 的 128×128 块,精度最好,已是主流);
- **激活的难点**:激活有 outlier channel,且分布随输入变化。SmoothQuant
  的思想:激活难量化、权重量化容易,那就用等价变换把激活的尺度"转嫁"
  给权重($Y = XW = (X/\mathrm{diag}(s))(\mathrm{diag}(s)W)$),
  让两者都变得平滑可量化;
- FP8 激活有时干脆**在线动态量化**(逐 token 算 scale),省去校准;
- 我们的卡:Ada(4080)与 Blackwell 消费卡(5070 Ti)都有 FP8 tensor core;
  Blackwell 还多了 FP4。FP16 模型的 FP8 版在 vLLM 里基本即下即用,
  权重减半、prefill 还能吃到接近翻倍的算力——**16 GB 卡跑 8B 时,
  FP8 是比 Q4 更均衡的选择**(质量几乎无损,代价是权重 8 GB 比 Q4 大)。

## 8. KV Cache 量化

长上下文场景 KV 才是显存大头(资源估算篇 §2),量化对象自然扩展到 KV:

- 常见 **FP8 KV**(vLLM/SGLang 开关即得):KV 显存减半,质量损失很小;
- 更激进的有 INT4 KV、以及 TurboQuant 这类把向量做旋转/残差量化的研究
  方案(可达 3 bit 量级);
- 直觉:K 决定注意力权重的"形状",V 决定被加权的"内容",两者敏感度
  不完全相同;工程上通常先 FP8 一刀切,收益/风险比已经很好;
- 注意 decode 时每个 token 都要读全部 KV,**KV 量化同样给 decode 提速**
  (上下文越长越明显)。

## 9. 选型实践

| 你的目标 | 建议 |
|---|---|
| 16 GB 卡,8B,要长上下文 | GGUF Q4_K_M(权重 5 GB,KV 充裕) |
| 16 GB 卡,8B,要质量 | FP8(vLLM,权重 ~8 GB)或 Q6_K |
| 16 GB 卡,14B | Q4_K_M(资源估算篇案例 C) |
| 极限压缩能跑就行 | Q3_K_M,但数学/代码任务慎用 |
| 生产 serving | FP8(硬件原生)+ FP8 KV |
| 代码/数学等高精度任务 | 量化档位提一档(Q6/Q8/FP8),位宽对推理链更敏感 |

通用法则:**模型大一档 + 量化低一档,通常优于模型小一档 + 量化高一档**
(14B Q4 > 8B Q6)。因为容量(参数量)带来的能力提升是实打实的,
而 Q4 级量化的质量损失在现代方案下已接近噪声水平。

## 10. 小结

- 量化 = 分组 + scale/zero-point;误差由组内取值范围决定,分组量化是
  精度与体积的主战场;
- GGUF K-quant 零校准即下即用;GPTQ 用二阶信息补偿;AWQ 用激活统计
  保护 salient channel;FP8 连计算一起降、还吃硬件红利;
- KV Cache 量化是长上下文的第二战场;
- 选型就一句话:**Q4_K_M 起步,质量敏感任务升档,生产上 FP8**。
