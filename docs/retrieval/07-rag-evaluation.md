# RAG 评估:指标、标注与归因

RAG 是两段系统,错误会叠加传播:检索漏了,生成再强也编不出没看到的内容。
评估因此必须**分段进行 + 端到端验证**。本篇给出完整方法:
检索指标的定义与性质、标注集怎么造、LLM-as-judge 的偏差与对策、
以及出问题时的归因方法。

## 1. 评估为什么难

- **级联误差**:总错误 = 检索错误 + 检索正确但生成用错,两者要分别计量;
- **开放生成**:答案没有唯一正确形式,字符串匹配(EM/F1)严重低估;
- **组件耦合**:换了 embedding 模型,chunk 策略可能也得跟着换,
  单变量对比很难做干净。

## 2. 检索指标:定义与性质

设标注好的相关文档集合为 $R$,系统返回 top-$k$ 列表。

| 指标 | 定义 | 看什么 | 何时用 |
|---|---|---|---|
| Recall@$k$ | $\|R \cap \text{top-}k\| / \|R\|$ | 召回覆盖(不看名次) | **RAG 检索层的第一指标**:只关心"进没进前 $k$",名次交给 rerank |
| Precision@$k$ | $\|R \cap \text{top-}k\| / k$ | 结果纯净度 | 库小、相关文档多时;大库里天然低,参考价值有限 |
| MRR | $1 / \text{rank}_1$(第一个相关文档名次的倒数) | 首个答案多靠前 | 单答案问答("有一个对的就够") |
| nDCG@$k$ | 见下 | 分级相关性的整体排序质量 | BEIR/MTEB 主指标,最终排序质量 |

nDCG 的定义:

$$\mathrm{DCG@}k = \sum_{i=1}^{k} \frac{2^{rel_i} - 1}{\log_2(i+1)},
\qquad \mathrm{nDCG} = \frac{\mathrm{DCG}}{\mathrm{IDCG}}$$

- $rel_i$:第 $i$ 名的相关性等级(0~3 级),IDCG 是理想排序的 DCG,
  相除后归一到 $[0, 1]$;
- **对数折扣**的直觉:第 1 名权重 1,第 2 名 0.63,第 10 名 0.29——
  排在前面的失误代价大,后面的近似免费;
- $2^{rel} - 1$ 的指数增益放大高等级相关的区分度。

RAG 场景的指标搭配:**召回层看 Recall@50,rerank 后看 nDCG@10,
问答型任务补 MRR**。

## 3. 标注集怎么造

- **规模**:100~500 个代表性问题即可启动,覆盖真实 query 的类型分布;
- **pooling 方法**(关键):从**多个不同系统**的 top-$k$ 取并集做标注。
  只用当前系统的召回结果标注,会系统性偏向它——
  它找不到的文档永远不会被标注为相关,新系统的优势测不出来;
- **LLM 预标注 + 人工抽检**:LLM 先判相关性,人工抽 10%~20% 核验,
  成本降一个数量级;抽检合格率决定能不能信这批标注。

## 4. 生成侧评估:LLM-as-judge

### 4.1 两个核心指标

- **Faithfulness(忠实度)**:答案的每个论断是否被检索片段蕴含。
  RAGAS 的做法值得拆开看:LLM 先把答案拆成**原子论断**,
  再逐条对 context 做蕴含判断(NLI 思路),忠实度 = 被支持的论断比例
  ——把"评估一整段"降为"判断一句句",可靠性高得多;
- **Answer Relevance**:答案是否回应了问题。
  一个巧妙的做法:让 LLM 从答案**反推问题**,
  与原问题算相似度——答非所问的答案反推不出原问题。

### 4.2 LLM 评判的已知偏差与对策

| 偏差 | 现象 | 对策 |
|---|---|---|
| 位置偏置 | 交换两个候选的位置,评判翻转 | 交换位置测两次,不一致则降权 |
| 长度偏置 | 偏好更长(未必更好)的答案 | rubric 里显式声明"长度不构成加分" |
| 自我偏好 | GPT-4 给 GPT-4 的答案打分偏高 | judge 与被评模型用不同家 |
| 直接打分不稳 | 分数漂移、复现差 | 先输出分析再打分;用 token 概率加权(G-Eval) |

## 5. 端到端与归因

- 有标准答案:LLM 判对错(比 EM/F1 宽容表述差异);
- **归因消融**:固定生成配置、只换检索配置,以及反过来——
  分别观察指标变化,定位瓶颈在哪段;
- 经验法则(重复 [01-rag.md](01-rag.md) §9):
  大多数"生成质量问题"实际是召回不足。
  先看 Recall@$k$ 里的 $k$ 是不是太小、再看 chunk 切分,
  最后才轮到 prompt 和模型。

## 6. 线上指标:离线评不到的东西

- **引用点击率**:用户是否点开来源——答案可信度的行为信号;
- **追问率/改写率**:用户换个说法重问 ≈ 对上一轮不满意;
- **兜底率**:"不知道"的回答占比——过高说明检索覆盖不足,
  过低(接近 0)反而要警惕幻觉;
- 离线评测集必须与线上 query 日志**分布对齐**并定期更新,
  否则指标只是自欺。
