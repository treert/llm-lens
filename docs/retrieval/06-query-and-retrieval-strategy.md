# 查询侧策略:改写、扩展与融合

检索模型只能按它**看到的 query** 工作,而用户的原始提问往往不适合直接检索:
太短、有指代、用词与文档不一致。本篇讲检索之前能做什么——
查询改写、HyDE、子问题分解,以及多路召回结果怎么融合。

## 1. 问题:用户的提问不是好 query

典型的失配场景:

- **多轮指代**:"它支持多少并发?"——"它"是谁只在对话历史里;
- **术语错位**:用户说"显存爆了",文档写的是"OOM"或"显存溢出";
- **粒度错位**:用户问的是宏大概念,答案却写在某个具体配置段落里。

检索侧的一切优化(索引、rerank)都救不了"query 本身就歪了"。
查询处理是整条链路的第一个瓶颈,也是性价比最高的优化点。

## 2. 多轮对话的指代消解

标准做法:检索前先用 LLM 把当前问题**改写为自足问题**:

```
输入:对话历史 + 当前问题("它支持多少并发?")
输出:自足问题("vLLM 的 continuous batching 支持多少并发?")
```

两个工程要点:

- 改写结果**只用于检索**,展示与最终回答仍基于用户的原始问题
  (改写可能引入错误,不能污染用户可见的内容);
- 改写是同步路径上的一次生成,延迟直接叠加——用小模型或短 prompt 控制成本。

## 3. HyDE:用假想答案检索

### 3.1 原理

检索发生在向量空间,而训练对是(问题, 答案):
**问题的向量分布与答案的向量分布存在系统性差异**——
问题以疑问句、短句为主,答案是陈述句、信息密集。
HyDE 让 LLM 先**编一段假想答案**(不需要正确,只需要"像答案"),
再编码去检索:变成"答案找答案",分布对齐了,向量距离天然更近。

### 3.2 流程与成本

```
问题 → LLM 生成 1~n 段假想答案 → 编码(多段取平均向量)→ 检索
```

代价是一次生成的延迟;采样多段取平均能压住单段编造的噪声。

### 3.3 何时有效、何时失效

- **有效**:零样本/无标注的新领域——HyDE 把 LLM 的通用知识
  变成检索器的"翻译器",不需要为 embedding 模型造训练数据;
- **失效**:模型完全不懂的领域会编错方向,
  假想答案里的幻觉直接传导给检索——越编越偏。
  判断依据:该领域的 baseline 检索召回是否已经太差。

## 4. 子问题分解与多跳检索

- **分解**:复杂问题让 LLM 拆成若干可独立回答的子问题,
  分别检索、分别作答、最后汇总;
- **多跳**:第一跳的答案决定第二跳查什么
  ("X 的妻子的母校是哪" → 先查 X 的妻子 → 再查其母校),
  检索由中间结论驱动——这已经摸到 agentic 的边(见
  [08-advanced-rag.md](08-advanced-rag.md));
- **风险是错误传播**:子问题分解错了,后面步步错;
  子问题之间的依赖要在分解时显式标出。

## 5. 混合检索的融合理论

### 5.1 分数不可比问题

BM25 分数无界(0~几十,随文档与 query 长度漂移),
余弦相似度有界 $[-1, 1]$——**直接加权求和没有意义**。
min-max 或 z-score 归一化看似解决了,但对分布形状极敏感:
一个离群高分就能把整个 min-max 区间拉爆。

### 5.2 RRF 为什么稳

RRF(Reciprocal Rank Fusion)干脆**不看分数只看名次**:

$$\mathrm{RRF}(d) = \sum_{r \in \text{rankings}} \frac{1}{k + r(d)}, \qquad k = 60$$

- 对各路分数的分布完全免疫(名次是序数,不是基数);
- $k$ 的作用:压制"单路第一"的爆发力—— $k$ 越小头部独大,
  $k$ 越大两路趋于平权平均;
- $k = 60$ 是论文在多个数据集上的经验值,且在 30~100 的宽区间内结果稳定
  ——这是个**鲁棒**的超参,不需要细调。

### 5.3 有标注时:学习融合

积累了标注数据后,可以训一个小模型(逻辑回归/GBDT)
学习两路分数的最优组合,收益能超过 RRF——
代价是引入训练维护成本与过拟合风险。没有标注时 RRF 就是终点。

## 6. 迭代检索:检索变成生成中的动作

更进一步的形态:生成过程中发现信息不足,主动触发新一轮检索
(self-RAG 的反思思路:"这步需要查吗?查到的相关吗?答案被支持吗?")。
此时检索不再是生成的前置步骤,而是生成中的一个可重复动作——
这条线的完整展开见 [08-advanced-rag.md](08-advanced-rag.md) §2。

## 7. 工程清单

| 策略 | 解决什么 | 额外成本 | 何时引入 |
|---|---|---|---|
| 指代消解改写 | 多轮指代 | 1 次小模型生成 | 有多轮对话就必备 |
| HyDE | 零样本领域术语错位 | 1~n 次生成 | 无标注新领域、baseline 召回差 |
| 子问题分解 | 复杂多跳 | n 次检索 + 汇总 | 分析型、比较型问题 |
| RRF 融合 | 稀疏+稠密混合 | ≈ 0 | 默认就开 |
| 迭代检索 | 单次检索覆盖不足 | 多轮检索+生成 | 见 08 的 agentic 形态 |

经验顺序:先把改写和 RRF 这两个"低成本无风险"的装上,
HyDE 与分解按失败 case 驱动引入。
