# 数据工程:预训练模型的真正配方

前置:[01-pretraining-overview.md](01-pretraining-overview.md)。
目标:理解预训练语料从哪来、清洗流水线每步在防什么、数据配比为什么
是核心超参数、tokenizer 的 BPE 与词表大小权衡。一句话:**模型是
数据的镜像,数据工作是 frontier 实验室与开源社区差距最大的环节**。

## 1. 语料来源与典型构成

现代预训练语料的五大来源:

| 来源 | 量级 | 角色 |
|---|---|---|
| 网页(Common Crawl 系) | 数十 T tokens(清洗后) | 主体,提供广谱知识与语言多样性 |
| 代码(GitHub 等) | 1~2 T | 提升逻辑与推理(见 §5) |
| 书籍/论文 | 数百 B | 长程连贯性、深度知识 |
| 百科/对话/论坛 | 数百 B | 事实性、对话模式 |
| 合成数据 | 比例上升中 | 教科书式改写、数学推理(Phi 路线) |

语言构成上英文主导(通常 >80%),多语言是长尾——这是开源模型
多语言能力参差不齐的根源。中文占比高的模型(Qwen、GLM)靠的是
**刻意提高中文配比**,不是自然分布。

## 2. 清洗流水线:六步

以开源语料集 FineWeb / RedPajama / DCLM 的做法为代表,原始网页
变成训练语料要过六关:

```
原始 HTML
 → 1. 文本提取    (去 boilerplate:导航栏、广告、页脚)
 → 2. 语言识别    (fastText 分类器,按语种分流)
 → 3. 质量过滤    (启发式规则 + 分类器打分)
 → 4. 去重        (exact dedup + MinHash 模糊去重)
 → 5. 安全过滤    (PII、有害内容、垃圾站)
 → 6. 去污染      (删除与评测集重叠的文本)
```

**质量过滤**的两种武器:

- 启发式规则:行长分布、重复行比例、特殊字符占比、词表外符号
  比例——规则简单但极度有效,能砍掉一半以上的机器生成垃圾
  (SEO 页、列表页);
- 分类器打分:训练一个小模型判断"这段文本像不像维基百科/教科书",
  低分丢弃。DCLM 的消融显示:**分类器选型是语料质量的最大单因素**。

**去污染**与微调数据的去污染同构(见 finetune 07 篇 §3),但规模
大到必须 n-gram + 哈希索引工程化。

## 3. 去重:为什么值得单独一节

网页语料的重复触目惊心(转载、模板、镜像站)。去重分两层:

- **精确去重**:URL 规范化 + 文档哈希,去掉完全相同的副本;
- **模糊去重(MinHash + LSH)**:把文档表示为 n-gram 集合,用
  MinHash 签名估计 Jaccard 相似度,LSH 分桶把 $O(N^2)$ 的两两比较
  压到近似线性——这是在大规模语料上可行的唯一方式。

收益不只是省 token:

1. **重复数据的边际收益递减**(Muennighoff et al.:同一份数据训
   4 个 epoch 内接近新数据,之后急剧衰减)——与其重复,不如去重后
   把算力花在新数据上;
2. **记忆化与隐私**:高频重复的文本会被模型逐字背下来(可提取性
   记忆),既是版权问题也是隐私问题;
3. loss 更平滑:重复模板会让模型学到捷径。

## 4. 数据配比:核心超参数

"配比"(domain mixture)指各来源数据在训练中的采样权重。它是
**与 lr 同等级别的超参数**,且更难调——配比的效果只有训完才能
完整评估。

已知的重要经验:

- **代码数据提升推理**:即使目标模型不写代码,混入 10%~20% 代码
  数据的模型在推理 benchmark 上显著更好(代码的逻辑结构外溢);
- **高质量数据后置**:最好的数据留到训练后期(退火)混入,收益
  最大(05 篇);
- **配比的实验方法**:在小模型(如 1B)上按 Chinchilla 配比训若干
  组对照,测下游 benchmark,选最优配比外推——这就是 01 篇时间线里
  "小规模实验"的主要工作之一;
- 配比不是静态的:现代做法是**分阶段配比**(课程式),早期广谱,
  后期精品。

## 5. Tokenizer 与 BPE

模型不读字符,读 token。主流 tokenizer 是 **BPE(字节对编码)**:

```
从字节级 256 个符号开始:
  1. 统计语料中所有相邻符号对的频率
  2. 合并最高频的一对为新符号,加入词表
  3. 重复,直到词表达到目标大小
```

**词表大小的权衡**(现代模型典型 32K~256K):

| 大词表(如 256K) | 小词表(如 32K) |
|---|---|
| 序列更短 → 训练/推理更快、有效上下文更长 | embedding/lm_head 参数更少 |
| 稀有词不用拆碎,表示更完整 | 稀有词碎成多 token,学习负担重 |
| embedding 参数占比升高 | 多语言 fertility 差(见下) |

**fertility**(平均每个词/字对应的 token 数)是 tokenizer 质量的
实操指标:fertility 高 = 同样的文本被切得更碎 = 更贵更慢更难学。
英文中心词表对中文的 fertility 常 >2(一个汉字两个 token 以上),
这是中文模型倾向自训词表的原因。

BPE 的另一个已知怪癖:**数字切分**。`123456` 可能被切成
`123`/`456` 或 `12`/`34`/`56`,不同模型不一致——这是 LLM 算术
能力差的经典解释之一(进位依赖的数位对齐被切分破坏)。Llama-3
之后倾向逐位切分数字缓解此问题。

## 6. 数据量的军备竞赛与合成数据

Chinchilla(03 篇)之后,业界共识从"堆参数"转向"堆数据":

- Llama-2:2T tokens → Llama-3:**15T** tokens;
- 高质量公开网页已被"吃完"(2026 年前后耗尽论),边际增长转向:
  多模态转文本(视频/音频转录)、**合成数据**。

合成数据的代表路线:Phi 系列用 GPT-4 生成"教科书质量"的讲解文本,
小模型(3B)在数学/推理上达到大模型水平——再次印证 01 篇的观点:
**能力来自数据分布,数据工程可以主动设计这个分布**。风险是模型自产
数据的近亲繁殖(对原创分布的坍缩),主流用法是"强模型生成 + 规则
过滤 + 与真实数据混合"。

## 7. 对个人的意义

- 读模型报告时,先看数据章:语料规模、清洗方法、配比、合成数据
  比例——这些比架构微调更能解释模型表现;
- 微调自己的模型时,02~04 节的所有概念(质量过滤、去重、配比)
  在几千条数据的尺度上同样成立(finetune 07 篇是它们的微观版);
- 评估一个开源数据集,先问:去重了吗?去污染了吗?fertility 如何?

## 8. 小结

$$\text{模型能力上限} \approx f(\text{数据量} \times \text{质量} \times \text{配比的合理性})$$

- 六步流水线:提取、语言识别、质量过滤、去重、安全、去污染,
  每步都在防一种具体的"垃圾进垃圾出";
- 配比是与 lr 同级的超参数,代码混入提升推理是最反直觉的经验;
- BPE 词表大小权衡速度与表示,fertility 是实操检测指标;
- 公开高质量文本趋于耗尽,合成数据是下一个战场。
