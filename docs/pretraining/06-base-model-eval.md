# 基座模型评估:怎么衡量一个"不会聊天"的模型

前置:[01-pretraining-overview.md](01-pretraining-overview.md)(base model
的能与不能);评估方法论与 [../finetune/07-data-and-eval.md](../finetune/07-data-and-eval.md)
互补(那篇讲微调后的行为评估,本篇讲预训练的能力评估)。
目标:理解 perplexity 的能与不能、base model 为什么用 few-shot 评测、
主流 benchmark 各测什么、以及怎么读一份开源模型的技术报告。

## 1. Perplexity:最古老也最诚实的指标

定义:模型在 held-out 文本上的平均负对数似然的指数:

$$\text{PPL} = \exp\Big( -\frac{1}{N} \sum_{t=1}^{N} \log p_\theta(x_t \mid x_{<t}) \Big)$$

就是训练 loss 的指数。读法:"模型平均在每个位置对多少个候选词
感到困惑"——越低越好。

**能做什么**:

- 训练中监控(它就是 validation loss 的化身);
- 同一数据分布下比较模型/数据配比,公平且灵敏;
- 检测异常:某类文本 PPL 突增 = 那类数据出了问题。

**不能做什么**:

- **不区分"重要的错误"**:预测错"的/地"与预测错关键实体,对 PPL
  贡献差不多,但对下游任务天差地别;
- 跨词表比较无意义(tokenizer 不同,token 粒度不同);
- 与下游能力的关系是相关而非因果:PPL 降到一定程度后,下游
  benchmark 继续涨而 PPL 几乎不动。

所以 PPL 是训练者的仪表盘,不是排行榜的裁判。

## 2. Base model 为什么用 few-shot 评测

base model 不会听指令(01 篇 §4),直接问"以下哪项正确?"它可能
续写题目而不是作答。评测要利用它唯一会的技能:**模式续写**——
给 $k$ 个完整的问答示例(few-shot),让它模仿格式续出答案:

```
Q: 水的化学式? A: H2O
Q: 光速约为? A: 3×10^8 m/s
Q: 法国的首都是? A:   ← 模型续写 "Paris"
```

这就是 benchmark 报告里 "5-shot MMLU"、"0-shot ARC" 的含义。
启示:base model 的分数是"潜力"而非"体验",普通用户接触到的
聊天表现取决于后训练——两个系列的分工在评估上同样清晰可见。

## 3. 主流 benchmark 各测什么

| Benchmark | 形式 | 测什么 | 备注 |
|---|---|---|---|
| MMLU | 57 科选择题 | 广谱知识与推理 | 接近饱和,区分度下降 |
| ARC / HellaSwag / WinoGrande | 选择/填空 | 常识推理 | 老牌,易被污染 |
| GSM8K / MATH | 数学应用题 | 推理链 | 对训练数据中的数学配比极敏感 |
| HumanEval / MBPP | 代码生成 | 编程 | pass@k 指标 |
| BBH | 27 个难任务 | 高阶推理 | 对 CoT 敏感 |
| NIAH(大海捞针) | 长文检索 | 长上下文 | 05 篇:满分 ≠ 长文推理可靠 |

两个读榜警告:

- **饱和**:头部模型在 MMLU 类榜单上挤在 85~90 分,差异已在
  噪声内——这时应看更难的继任者(MMLU-Pro、GPQA、AIME);
- **污染**:benchmark 题面遍布网络,预训练语料几乎必然摄入
  (02 篇 §2 去污染就是为了这个)。识别方法:看模型在"题目略改
  数字/表述"的变体集上是否掉分(GSM1k 研究:部分模型掉分显著,
  说明记忆而非推理)。

## 4. 训练过程监控:评估的另一面

预训练期间的评估是"边飞边修引擎":

- **loss/grad norm 曲线**(04 篇 §5):最早的健康信号;
- **中途 benchmark**:每若干 step 在固定评测集上测一次,画出
  能力-步数曲线——用于验证 scaling 外推(03 篇)是否兑现,以及
  决定何时停、何时进退火;
- **数据归因**:某 benchmark 中途异常,反查对应数据配比/批次。

## 5. 怎么读一份开源模型技术报告

按信息密度排序,重点看:

1. **数据章**:语料规模、配比、合成数据比例、去污染方法——
   模型的真正配方(02 篇);
2. **训练章**:$N$、 $D$、 $C=6ND$、MFU、spike 与对策(04 篇);
3. **配置表**:层数/宽度/词表/上下文,心算 $D/N$ 判断训练策略
   (03 篇);
4. **评测章**:看评测是 few-shot 还是 instruct 版、有没有变体集
   抗污染验证、长上下文除了 NIAH 还有什么;
5. **没写什么**:不公布数据配比的、只报饱和榜单的、没有失败
   记录的,都说明有所保留。

## 6. 对个人的意义

- 微调自己的模型时:held-out loss 是你的 PPL(过程指标),
  程序化检查与人工抽检是你的 benchmark(结果指标)——两套都要,
  缺一不可(finetune 07 篇 §5);
- 选基座模型时:少看总分,多看与目标场景对应的单项分 + 数据
  配比里有没有对应领域;
- 评估永远要问:这个分数是"能力"还是"记忆"?

## 7. 小结

- PPL 是训练仪表盘,benchmark 是能力快照,两者互补不可互换;
- base model 用 few-shot 续写评测,分数是潜力不是体验;
- 读榜三问:饱和了吗?污染了吗?是记忆还是推理?
- 评估方法与监控意识,是本系列留给个人实操(finetune 08 篇)
  最直接的遗产。
