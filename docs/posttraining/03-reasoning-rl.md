# 推理模型 RL:R1 配方拆解与小规模复现

前置:[../finetune/06-preference-alignment.md](../finetune/06-preference-alignment.md)
(GRPO 公式、RLVR 概念)、[02-distillation.md](02-distillation.md)(蒸馏是
RL 的替代/起点)。
目标:拆解 DeepSeek-R1 的完整后训练配方,理解 R1-Zero 纯 RL 实验
为什么震撼业界,奖励设计(ORM/PRM/规则)的权衡,并在单卡上复现
"思维链变长"现象。

## 1. R1 之前:RL 用于推理的三个障碍

- **奖励稀疏**:一道数学题只有最终结果对错一个 bit 的信号,而
  轨迹有上千 token;
- **探索空间巨大**:长思维链在 base 分布中概率极低,随机探索几乎
  撞不到;
- **critic 太贵**(finetune 06 篇 §3):PPO 需要与 policy 同规模的
  价值模型。

R1 的答案是:规则化可验证奖励 + GRPO(组内 baseline 替代 critic)+
从已经很强的 base 出发。

## 2. R1-Zero:纯 RL 的震撼实验

做法:DeepSeek-V3-Base(**不经过任何 SFT**)直接上 GRPO,奖励只有
两条规则:

$$r = r_{\text{正确}} + r_{\text{格式}}
= \mathbb{1}[\text{最终答案正确}] + \lambda\,\mathbb{1}[\text{思维链放在指定标签内}]$$

观察到的现象:

- AIME pass@1 从 ~16% 涨到 ~71%(多数投票 ~87%);
- **"aha moment"**:训练中模型自发学会在推理中途停下来自我纠正
  ("等等,这里不对,重新算")——没有任何人教过它反思;
- **平均响应长度持续增长**:探索发现了"想得久→对得多"的策略。

也有明显缺陷:**可读性差、语言混杂**(中英夹杂、格式混乱)——
base 模型没有"说人话"的约束。这引出 R1 的完整配方。

## 3. R1 的四阶段配方

```
阶段 1:冷启动 SFT
  数千条人工精修的长思维链数据,微调 base
  → 目的:固定可读的思维链格式,给 RL 一个好的探索起点
阶段 2:推理导向 RL(主体)
  GRPO + 规则奖励,专注数学/代码/逻辑,算力大头在这里
  → 能力的主要来源
阶段 3:拒绝采样 + 全场景 SFT
  用阶段 2 的模型对大量 prompt 采样,verifier/人工筛掉错的
  (~60 万推理条)+ 通用能力数据(~20 万条),重新 SFT
  → 把 RL 学到的能力"蒸馏回自己",同时补上通用对话
阶段 4:全场景 RL
  规则奖励(推理)+ 偏好 RM(有帮助性/无害性)混合
  → 对齐人类偏好的收尾
```

值得注意的设计逻辑:**SFT 与 RL 交替,各解决对方的问题**——SFT 解决
RL 的起点与可读性,RL 解决 SFT 到不了的能力上限,拒绝采样(阶段 3)
本质是一次自蒸馏(02 篇的方法用在自家模型上)。

## 4. 奖励设计:ORM vs PRM vs 规则

| 奖励 | 信号粒度 | 优点 | 缺点 |
|---|---|---|---|
| **规则/verifier** | 最终结果 | 零成本、不可 hack | 只能用于有标准答案的任务 |
| **ORM**(结果奖励模型) | 最终结果 | 可用于开放任务 | 仍是稀疏信号 |
| **PRM**(过程奖励模型) | 每一步推理 | 信号密、可定位错误步 | 标注极贵、易被 hack(模型学会"写出讨 PRM 喜欢的步骤") |

R1 的选择:能用规则就用规则(数学/代码),开放任务才用 RM;
**明确放弃 PRM**(论文给出三个理由:难定义"正确的中间步骤"、
标注成本高、reward hacking)。这是推理 RL 时代的重要风向:
**可验证任务优先,模型化奖励退居二线**。

## 5. 复现运动与个人可行性

R1 公开后,多个开源项目在小规模上复现了核心现象:

- **TinyZero**:Countdown 数字游戏(给几个数字凑目标值),
  Qwen2.5-3B,纯 GRPO,成本 **<$30**——观察到响应长度增长与
  自我反思语句出现;
- OpenR1、simpleRL 等:GSM8K/数学上复现类似现象。

结论:**"思维链变长"不是 671B 模型的专利,小模型小任务上同样
涌现**——这正是个人可以亲手观察的部分。复现不了的是能力的绝对
水平(那需要 base 足够强 + 算力足够多)。

## 6. 动手:16 GB 上的 mini R1-Zero

配置(unsloth 的 QLoRA-GRPO 路线,采样由训练进程内嵌的 vLLM 完成):

| 项 | 选择 | 理由 |
|---|---|---|
| 模型 | Qwen2.5-3B(-Instruct 或 base) | 3B 是 16 GB 上 GRPO 的甜点位;8B 需大幅压缩生成长度与组大小 |
| 任务 | GSM8K 训练集 或 Countdown | 都有免费的程序化 verifier |
| 奖励 | 答案正确(主)+ 格式标签(辅) | 复刻 R1-Zero 的 $r_{\text{正确}} + r_{\text{格式}}$ |
| GRPO 组大小 G | 4~8 | 显存换探索广度,G 越大 baseline 越稳 |
| 生成长度 | 512~1024 | 长 CoT 是显存与吞吐大头 |

显存粗账(3B):4bit 主干 ~2 GB + LoRA 状态 <1 GB + 采样与激活
峰值 ~6~8 GB → **16 GB 可行**(对照 finetune 02 篇的算法)。

训练循环与 SFT 的本质差异:

```
for step:
    对一批 prompt,每个采 G 条回答(在线生成,吞吐瓶颈)
    规则打分 → 组内标准化得优势 A_i = (r_i - mean)/std
    按 GRPO 目标更新 LoRA 参数
```

观察指标(写进训练日志,对应本仓库"实测对账"传统):

1. **奖励曲线**:应缓慢爬升;先涨的通常是格式分;
2. **平均响应长度**:核心现象——若训得动,应看到长度先稳后升;
3. **生成样本抽读**:几百 step 后寻找自我纠正语句("不对/重新算/
   wait")的出现——这就是 mini 版 aha moment。

预期管理:3B + 几百步,能看到**格式学会、长度变化、偶发反思**,
看不到真正的推理质变。实验目的是亲手验证 §2 的现象,不是产出
可用的推理模型——要可用的,回 02 篇蒸馏。

## 7. 小结

- R1-Zero 证明:足够强的 base + 规则奖励 + GRPO,纯 RL 就能涌现
  长思维链与自我反思;
- R1 的配方 = SFT 与 RL 交替的四阶段,各自补对方的短板;
- 奖励设计的风向:规则奖励优先,PRM 被弃,模型化奖励退守开放任务;
- 个人路径:小模型小规模复现现象(本篇),蒸馏获取能力(02 篇),
  两者结合就是"穷人版 R1"。
