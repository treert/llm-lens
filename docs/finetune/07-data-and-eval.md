# 数据工程与评估:微调的真正瓶颈

前置:[03-full-finetuning.md](03-full-finetuning.md)。
目标:建立两个信念——**数据质量是微调效果的上限,算法只是逼近上限的
手段**;以及知道微调完之后怎么严谨地回答"它变好了吗"。

## 1. 表面对齐假说:1000 条数据的震撼

LIMA(Meta, 2023)用 **1000 条**人工精选的指令数据微调 65B 模型,
效果逼近用 5 万条数据微调的 DaVinci003。作者据此提出"表面对齐假说
(Superficial Alignment Hypothesis)":

> 模型的知识与能力几乎全部在预训练时习得;对齐(微调)只是教模型
> 在与用户交互时**调用哪种子分布、用什么格式**。

这条假说是整个数据工程的方法论基石:

- 数据**质量与多样性**远比数量重要;
- 微调不擅长注入新知识(01 篇 §3 的佐证);
- 几百~几千条精数据是个人微调的甜点位——这在工程上是个好消息。

## 2. 指令数据的四条来源路线

| 路线 | 做法 | 优点 | 风险 |
|---|---|---|---|
| 人工编写 | 自己/标注团队写 | 质量天花板 | 贵、慢 |
| 蒸馏强模型 | 让 GPT-4 级模型生成回答 | 便宜量大 | 受 ToS 限制;错误被照抄;"学形不学神" |
| Self-Instruct | 模型自造指令+回答,规则过滤 | 指令多样性好 | 需要强种子模型 |
| Evol-Instruct | 迭代改写指令(加约束、加步骤)提升复杂度 | 能造高难度数据 | 演化过头会脱离真实分布 |

个人实操的常见组合:**人工写几百条核心样本定调子,蒸馏/演化扩量,
再人工抽检**。

## 3. 质量控制清单

**过滤**(AlpaGasus 的证据:52K 条 Alpaca 数据用强模型打分筛到 9K,
效果反而更好):

- 删除过短/过长的回答、拒答样板("作为 AI 我不能...");
- 删除事实性错误(蒸馏数据必须抽验);
- 删除格式噪声(多余 markdown、乱码、中英混杂失控)。

**去重与多样性**:

- 语义去重(embedding 聚类后每簇留代表),重复样本会教出复读机;
- 检查指令类型分布(问答/改写/推理/创作...)是否覆盖目标场景,
  单一类型占比过高会让模型"什么都说成那种腔调"。

**去污染**:训练数据不得含评测集的题面或答案(n-gram 重叠检查,
如 13-gram)。污染的评测分数毫无意义,且极易在公开数据集里踩到。

**配比**:多任务混合训练时,别让大数据集淹没小数据集——按
sqrt 采样或设上限截断。

## 4. chat template 一致性:最廉价的翻车点

训练时序列怎么拼,推理时就必须怎么拼。具体核对:

- 特殊 token 是否完整(BOS/EOS/角色头尾),EOS 是否在回答末尾且
  计入 loss(03 篇 §2);
- 换行、空格、缩进与框架默认是否一致(unsloth/TRL 的
  `apply_chat_template` 与推理引擎的 template 要同源);
- 基座模型换代时 template 可能变(如 Qwen2→Qwen3 加了 think 段),
  老数据要重格式化。

症状:模型学会了内容但不肯停、说话带奇怪的标记残渣——九成是
template 错位。

## 5. 评估:怎么回答"变好了吗"

按可靠性从高到低:

**1. 人工盲评(金标准)**:微调前后模型各回答同一批 30~100 条
held-out prompt,打乱顺序盲选哪个好,报胜率。量小但结论最实。

**2. LLM 裁判(pairwise 胜率)**:让强模型当裁判,对比 A/B 两版输出。
必须控制两个已知偏差:

- **位置偏差**:交换 A/B 顺序各评一次,取一致结果;
- **长度偏差**:裁判普遍偏爱长回答,报告中要带长度分布;
- 裁判与被测模型的"亲缘关系"(同源模型互评偏高)也要警惕。

**3. 目标任务的程序化指标**:分类准确率、JSON 解析成功率、
正则匹配通过率——任务能程序判定时最省事,优先于一切主观评估。

**4. 通用 benchmark(MMLU 等)**:对微调带来的**行为变化不敏感**,
主要用途是回归测试——确认没有灾难性遗忘(03 篇 §5),而不是证明
微调有效。

**5. eval loss**:训练过程的监控信号(过拟合刹车),**不是**效果指标:
eval loss 低只说明拟合了同分布数据,不代表回答质量高。

## 6. 常见失败模式速查

| 症状 | 最可能原因 |
|---|---|
| 生成不停、越说越长 | EOS 没进 loss / template 错位 |
| 复读、循环输出 | 数据大量重复 / epoch 太多过拟合 |
| 回答变得极短 | 训练数据回答普遍短,模型学到了"短" |
| 通用能力明显退化 | lr 太大 / 全量微调未混通用数据(遗忘) |
| 格式对内容错 | 蒸馏数据本身有错,被忠实模仿 |
| benchmark 涨了但不会干活 | 训练集被 benchmark 污染 |

## 7. 小结

- 数据上是"质量 > 多样性 > 数量",LIMA 的 1000 条是个人微调的
  精神标杆;
- template 一致性是最廉价也最常见的翻车点;
- 评估的最小可信组合:程序化指标(若有)+ LLM 裁判控偏差 + 人工
  抽检 + 通用 benchmark 防遗忘;
