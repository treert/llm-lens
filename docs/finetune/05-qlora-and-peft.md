# QLoRA 与其他 PEFT:把冻结主干也压到 4 bit

前置:[04-lora.md](04-lora.md)、[02-training-memory.md](02-training-memory.md)、
`docs/inference/04-quantization.md`(量化的数学)。
目标:理解 QLoRA 三大件(NF4、双重量化、paged optimizer)的原理,
训练态量化与推理态量化的异同,以及 PEFT 家族的选型法则。

## 1. QLoRA 的动机:LoRA 之后还剩什么

04 篇把梯度+优化器从 112 GB 压到 ~1.6 GB,但 02 篇 §4 的账里还有
一项纹丝不动:**冻结主干本身**。7B 的 bf16 权重 ~15 GB,单独就把
16 GB 卡顶满。冻结权重不需要梯度、不需要更新,它的唯一职责是
**在前向/反向时被读到**——这正是量化可以下手的场景。

QLoRA(Dettmers et al., 2023)= **4 bit 量化冻结主干 + bf16 LoRA 旁路**,
配套三个技术件。

## 2. 三大件

### 2.1 NF4:为正态分布量身定做的 4 bit 数据类型

推理系列 04 篇 §2 的均匀量化(round-to-nearest)对权重不是最优:
预训练权重近似零均值正态分布,均匀网格把稀少的编码点浪费在尾部。

NF4(4-bit NormalFloat)的做法:把权重按块归一化到 [-1, 1] 后,
用 **N(0,1) 的分位数**当量化码本——16 个编码点对应 16 个等概率区间:

$$q_k = \Phi^{-1}\!\big( \tfrac{k + 0.5}{16} \big) \ \text{的归一化版},
\qquad k = 0, \dots, 15$$

每个区间落进等量的权重 → 信息论意义下 4 bit 的最优码本(对正态
数据)。与推理常用的 GGUF Q4(均匀+分组 scale)相比,NF4 是同
bit 数下更精致的码本设计;代价是反量化要查表,不适合推理热路径,
但训练里反量化在 kernel 内完成,无所谓。

### 2.2 双重量化(Double Quantization):连 scale 也量化

分块量化每个块要存一个 scale:块大小 64 时,fp32 scale 带来
$32/64 = 0.5$ bit/参数 的元数据开销(4 bit 的 12.5%)。双重量化把
256 个 scale 再组成一块,用 fp8 二次量化:

$$0.5\ \text{bit} \;\rightarrow\; \frac{8}{256} + \frac{32}{64 \times 256}
\approx 0.127\ \text{bit/参数}$$

7B 模型省下约 $7\times10^9 \times 0.373 / 8 \approx 0.33$ GB。单看不大,
但这是"纯白捡"——论文实测对精度无可测影响。

### 2.3 Paged Optimizer:防峰值 OOM 的保险丝

长序列样本进场时激活骤增,优化器状态的瞬时分配可能顶爆显存。
paged optimizer 借助 NVIDIA 统一内存(unified memory),把优化器状态
放在可自动换页到 CPU RAM 的页上:平时在显存,峰值挤出时自动换出,
防止一夜训练死在第 N 小时。代价是换页时的 PCIe 带宽开销——
**它是保险丝不是加速器**,正常情况不该触发;频繁触发说明配置太激进。

## 3. 训练态量化 vs 推理态量化

| | 推理量化(W4A16) | QLoRA |
|---|---|---|
| 存储 | 权重 4 bit | 主干 4 bit |
| 计算 | kernel 内反量化回 bf16 计算 | **同样**反量化回 bf16 计算 |
| 梯度 | 无 | 主干不回传梯度(视为常量),梯度只流向 LoRA |
| 精度目标 | 输出 logits 尽量接近 | 训练动态尽量接近全量微调 |

关键理解:**QLoRA 里 4 bit 只是存储格式,前向和反向的计算图全部在
bf16 上进行**。反量化是确定性函数,主干权重按常量处理,不需要它的
梯度;LoRA 分支全程 bf16,接收完整梯度。所以 QLoRA 训练的"精度损失"
只来自一件事:LoRA 旁路修正的基准点是反量化后的 $\hat{W}_0$ 而不是
原始 $W_0$。

由此推出 merge 时的细节(04 篇 §6 提到的缝隙):理想做法是
**merge 回原始 bf16 主干**($W_0 + \frac{\alpha}{r}BA$),而不是
merge 回反量化的 $\hat{W}_0$——前者让量化噪声在 merge 后完全消失,
只保留"LoRA 是照着 $\hat{W}_0$ 学的"这一点偏差。论文与后续复现的
结论:7B~65B 上 QLoRA 与全量 bf16 微调的效果差距在噪声范围内
(Guanaco-65B 在单张 48 GB 卡上达到 ChatGPT 99.3% 的 Vicuna 评分)。

## 4. PEFT 家族其他成员

| 方法 | 改动位置 | 可训练参数 | 推理开销 | 现状 |
|---|---|---|---|---|
| **LoRA/QLoRA** | 线性层旁路 | ~0.1%~1% | merge 后为零 | **事实标准** |
| Adapter | block 内串行插入 bottleneck 层 | ~1%~3% | **永久增加层深与延迟** | 基本被 LoRA 取代 |
| Prefix tuning | 每层 KV 前缀(软提示) | ~0.1% | 占用上下文长度 | 效果弱于 LoRA |
| Prompt tuning | 仅输入 embedding 前缀 | 极少(~万级) | 占用上下文长度 | 只够轻量任务 |
| IA3 | 逐通道缩放向量 | 极少 | 接近零 | 极轻量场景 |

LoRA 胜出的原因:不改架构(对比 Adapter)、不吃上下文(对比
Prefix/Prompt)、merge 后零开销、效果最接近全量微调。

## 5. 选型法则

```
需要微调?
├─ 学全新知识/新语言、预算充足 → 全量微调(03 篇)
├─ 默认:格式/风格/任务适配    → LoRA,bf16 主干(显存够的话)
├─ 单卡 16~24 GB、7B~14B      → QLoRA(本系列 08 篇)
├─ 极限参数压缩/嵌入式         → IA3 / Prompt tuning
└─ 一个基座服务多任务          → LoRA 不 merge,vLLM 多 adapter
```

经验补充:

- 14B 是 16 GB 卡 QLoRA 的实际上限(主干 4bit ~8.5 GB + 激活);
- 24 GB 卡(RTX 4090/5090)舒适区到 32B 级(4bit ~19 GB,需压激活);
- QLoRA 的 r 可以适当比 LoRA 大一点(如 32~64),补偿量化噪声,
  但证据不强,默认仍 16 起步。

## 6. 小结

- QLoRA = NF4(正态分位数 4bit)+ 双重量化(scale 再量化)+
  paged optimizer(换页保险丝),把冻结主干压到 ~4.5 GB(7B);
- 4 bit 是存储格式,计算全程 bf16,梯度只流 LoRA——与推理 W4A16
  同构,但目标不同;
- PEFT 选型一句话:**默认 LoRA,显存不够 QLoRA,其余方法了解即可**;
- 至此"怎么训"的工具箱齐了。下一篇换信号源:从"模仿标准答案"
  (SFT)升级到"学会比较好坏"(偏好对齐)。
